### 2.3 ADR-002 P0 阶段分组并行执行

- **Status**：Accepted
- **Context 准确性**：✅ 通过
  - 准确识别"P0 内部无 P0→P0 强依赖"
  - 主动修正 v1.0 的"THEME-B-01 → THEME-B-02"依赖错误
  - 准确引用并发文件修改规范
- **Decision 合理性**：⚠️ 需调整
  - 4 个并行组划分基于文件隔离原则合理
  - **矛盾点**：Decision 描述"4 个并行组文件隔离执行，组内串行、组间并行"，但 R22 风险描述"单人 Agent 4 组并行退化为串行执行（主 Agent 单线程，4 组无法真正并行）"，缓解措施为"接受串行现实，按组顺序执行（A→B→C→D）"
  - 两者对"并行"的描述矛盾：Decision 说组间并行，R22 说实际是串行
  - **建议**：修改 ADR-002 Decision 描述，明确"组间逻辑并行但物理串行执行（主 Agent 单线程）"，与 R22 缓解措施保持一致
- **Consequences 完整性**：⚠️ 需调整
  - 正向 Consequences 说"4 个并行组文件隔离执行"，但实际是串行执行
  - **建议**：修正为"4 个组按文件隔离原则顺序执行，避免并发冲突"
- **Alternatives 充分性**：✅ 通过
  - 备选 A（完全串行）/ B（子代理无序并行）/ C（原依赖错误）/ D（保持原 10 项）否决理由均充分
- **Drawbacks 识别**：✅ 通过
  - 识别"主 Agent 协调工作量增加"
- **跨 ADR 一致性**：❌ 与 R22 矛盾
- **评估结论**：⚠️ 需调整
- **理由**：Decision 与 R22 对"并行 vs 串行"的描述矛盾，需统一表述
- **严重程度**：严重

### 2.12 ADR-010b 主题包云端同步

- **Status**：Accepted
- **Context 准确性**：✅ 通过
  - 准确评估用户价值 3.3（P2）
  - 准确说明用户额外负担显著（需配置 WebDAV）
- **Decision 合理性**：❌ 需调整
  - **问题 1（严重）**：冲突合并策略过于简化
    - 仅说"基于时间戳的合并策略，冲突时用户选择保留版本，本地备份后再合并"
    - **未说明**：多设备并发编辑时的冲突检测机制、版本号管理、合并算法详细流程、三方合并（本地+云端+历史版本）策略
    - **建议**：补充冲突合并详细流程图与算法说明
  - **问题 2（严重）**：加密密钥丢失恢复机制缺失
    - 说"密钥由用户密码派生（PBKDF2）"
    - **未说明**：用户忘记密码时的恢复机制，可能导致云端数据永久无法解密
    - **建议**：补充"密钥恢复机制（如安全提示问题 / 备份恢复密钥 / 本地加密密钥备份）"
- **Consequences 完整性**：⚠️ 需调整
  - 未充分说明云端同步失败的回退策略细节
- **Alternatives 充分性**：✅ 通过
  - 备选 A（不实施云端同步）/ B（第三方云盘 SDK）/ C（WebDAV 标准协议）否决理由充分
- **Drawbacks 识别**：✅ 通过
- **跨 ADR 一致性**：✅ 与 ADR-010a 拆分合理

## 5. 实施阶段问题识别

### 5.1 ADR 实施阶段问题

#### 5.1.1 ADR-002 实施问题

**问题**：Decision 描述"4 个并行组文件隔离执行，组内串行、组间并行"，但 R22 缓解措施说"接受串行现实，按组顺序执行（A→B→C→D）"

**实施阶段影响**：
- 实施人员可能误以为可以真正并行执行 4 组任务
- 实际上主 Agent 单线程，4 组只能顺序执行
- 可能导致进度估算错误

**建议**：
- 修改 ADR-002 Decision 描述为"4 个组按文件隔离原则顺序执行（A→B→C→D），组内无依赖项可借用子代理分担分析"
- 与 R22 缓解措施保持一致

#### 5.1.2 ADR-010b 实施问题

**问题 1**：冲突合并策略过于简化

**实施阶段影响**：
- 多设备并发编辑时无法正确检测冲突
- 可能导致用户数据丢失

**建议**：补充冲突合并详细流程图与算法说明

**问题 2**：加密密钥丢失恢复机制缺失

**实施阶段影响**：
- 用户忘记密码时云端数据永久无法解密
- 可能导致用户数据永久丢失

**建议**：补充密钥恢复机制（如安全提示问题 / 备份恢复密钥 / 本地加密密钥备份）

#### 5.1.3 ADR-013 实施问题

**问题**：数据库迁移范围遗漏 pureSearch 字段

**实施阶段影响**：
- RSS-B-04 pureSearch 字段实施时可能遗漏数据库迁移
- 可能导致运行时崩溃或数据丢失

**建议**：在 ADR-013 中补充 RSS-B-04 pureSearch 字段的迁移说明

#### 5.1.4 ADR-015 实施问题

**问题**：借鉴代码重构策略缺失

**实施阶段影响**：
- 借鉴 Archive 项目的异步代码可能保留原项目的协程风格
- 可能导致代码风格不统一

**建议**：补充第 6 条"借鉴代码重构策略"

#### 5.1.5 ADR-019 实施问题

**问题**：P0 实施时机不明确

**实施阶段影响**：

- 若 ADR-019 未在 P0 实施 HTTPS 强制，可能引入安全风险

**建议**：明确 P0 阶段所有新增网络请求必须遵循 HTTPS 强制策略

#### 5.1.6 ADR-022 实施问题

**问题**：minSdk 21 vs 23 矛盾

**实施阶段影响**：
- 实施人员可能误用 minSdk 21

**建议**：统一为 minSdk 23

## 8. 发现的问题

### 8.1 严重问题（6 项）

#### 8.1.1 严重问题 1：ADR-002 与 R22 描述矛盾

- **位置**：ADR-002 Decision / R22
- **问题**：ADR-002 Decision 说"4 个并行组文件隔离执行，组内串行、组间并行"，R22 缓解措施说"接受串行现实，按组顺序执行（A→B→C→D）"
- **影响**：实施人员可能误以为可以真正并行执行 4 组任务，导致进度估算错误
- **修复建议**：修改 ADR-002 Decision 描述为"4 个组按文件隔离原则顺序执行（A→B→C→D），组内无依赖项可借用子代理分担分析"

#### 8.1.2 严重问题 2：ADR-013 数据库迁移范围遗漏 pureSearch 字段

- **位置**：ADR-013 / 图 6
- **问题**：ADR-013 仅提及 THEME-B-04 和 VIDEO-E-01 涉及数据库 schema 变更，但 RSS-B-04 pureSearch 字段也属于 schema 变更，未在 ADR-013 中提及
- **影响**：RSS-B-04 实施时可能遗漏数据库迁移，导致运行时崩溃或数据丢失
- **修复建议**：在 ADR-013 中补充 RSS-B-04 pureSearch 字段的迁移说明，同步修改图 6

#### 8.1.3 严重问题 3：文件清单遗漏 strings.xml / AndroidManifest.xml / proguard-rules.pro

- **位置**：§4 文件变更清单
- **问题**：
  - strings.xml 未列入文件清单（违反 ADR-018）
  - AndroidManifest.xml 未列入文件清单（RssSearchActivity 启动崩溃）
  - proguard-rules.pro 未列入文件清单（Release 包反射失败）
- **影响**：实施时可能遗漏这些文件的修改，导致功能异常
- **修复建议**：在 §4 文件变更清单补充这 3 个文件的修改项

#### 8.1.4 严重问题 4：ADR-022 minSdk 矛盾

- **位置**：ADR-022 Decision 第 1 条 / Alternatives 备选 B
- **问题**：Decision 第 1 条说"minSdk 23 不变"，Alternatives 备选 B 说"保持 minSdk 21（推荐）→ 采纳"
- **影响**：实施人员可能误用 minSdk 21，导致 rhino 1.8.1 在 API 21-23 设备上运行时崩溃
- **修复建议**：统一为 minSdk 23，删除 Alternatives 备选 B 中的 minSdk 21 描述

#### 8.1.5 严重问题 5：ADR-010b 冲突合并策略过于简化

- **位置**：ADR-010b Decision
- **问题**：仅说"基于时间戳的合并策略，冲突时用户选择保留版本"，未说明多设备并发编辑时的冲突检测机制、版本号管理、合并算法详细流程
- **影响**：多设备并发编辑时无法正确检测冲突，可能导致用户数据丢失
- **修复建议**：补充冲突合并详细流程图与算法说明

#### 8.1.6 严重问题 6：ADR-010b 加密密钥丢失恢复机制缺失

- **位置**：ADR-010b Decision
- **问题**：说"密钥由用户密码派生（PBKDF2）"，但未说明用户忘记密码时的恢复机制
- **影响**：用户忘记密码时云端数据永久无法解密，导致用户数据永久丢失
- **修复建议**：补充密钥恢复机制（如安全提示问题 / 备份恢复密钥 / 本地加密密钥备份）

### 8.2 中等问题（10 项）

#### 8.2.1 中等问题 1：ADR-006 与 ADR-004 冲突

- **位置**：ADR-006 / ADR-004
- **问题**：ADR-006 锁定依赖基线仅包含 10 项核心依赖，未涵盖 ADR-004 引入的新增 UI 依赖（liquidglass/lottie）
- **影响**：新增 UI 依赖可能引入未评估的传递依赖，导致兼容性问题
- **修复建议**：在 ADR-006 或 ADR-004 中补充新增 UI 依赖的评估要求

#### 8.2.2 中等问题 2：ADR-015 借鉴代码重构策略缺失

- **位置**：ADR-015 Decision
- **问题**：未说明借鉴 Archive 项目代码时的重构策略
- **影响**：借鉴代码可能保留原项目的协程风格，导致代码风格不统一
- **修复建议**：补充第 6 条"借鉴代码重构策略"

#### 8.2.3 中等问题 3：ADR-019 实施时机问题

- **位置**：ADR-019
- **问题**：未明确 P0 阶段是否必须实施 HTTPS 强制
- **影响**：P0 RSS-B-01 多源并发搜索已涉及网络请求，若未实施 HTTPS 强制可能引入安全风险
- **修复建议**：明确 P0 阶段所有新增网络请求必须遵循 HTTPS 强制策略

#### 8.2.4 中等问题 4：ADR-020 与 ADR-016 测量重叠未协调

- **位置**：ADR-020 / ADR-016
- **问题**：两者在"P0 前建立基线"方面重叠，但未协调测量内容
- **影响**：可能重复测量性能指标，导致工作量增加
- **修复建议**：明确 ADR-016 负责测试方法学，ADR-020 负责预算上限

#### 8.2.5 中等问题 5：ADR-021 异常分类标准缺失

- **位置**：ADR-021 Decision
- **问题**：仅说"业务异常 + 网络异常 + IO 异常 + 数据库异常"，未说明各类异常的具体判定标准
- **影响**：实施时可能无法正确分类异常，导致错误处理不一致
- **修复建议**：补充异常分类判定标准表

#### 8.2.6 中等问题 6：ADR-024 测试覆盖率工具配置缺失

- **位置**：ADR-024 Decision
- **问题**：要求使用 JaCoCo 测量覆盖率，但未说明 JaCoCo 的配置方式
- **影响**：无法生成覆盖率报告，无法验证 60% 覆盖率要求
- **修复建议**：补充 JaCoCo 配置示例

#### 8.2.7 中等问题 7：ADR-025 灰度发布与项目实际不符

- **位置**：ADR-025 Decision
- **问题**：要求灰度发布（10% → 50% → 全量），但本项目是开源项目，没有灰度发布基础设施
- **影响**：实施时无法执行灰度发布，可能导致发布流程阻塞
- **修复建议**：调整为 GitHub Release 分阶段发布

#### 8.2.8 中等问题 8：ADR-026 与 ADR-011 代码验证重叠

- **位置**：ADR-026 / ADR-011
- **问题**：两者在"代码审查 + 静态分析"方面重叠
- **影响**：实施时可能重复执行代码审查与静态分析，导致工作量增加
- **修复建议**：明确 ADR-011 与 ADR-026 的职责分工

#### 8.2.9 中等问题 9：ADR-027 响应时间与项目实际不符

- **位置**：ADR-027 Decision
- **问题**：要求高优先级问题 < 24h 响应，但本项目是单人维护项目
- **影响**：无法保证 24h 响应，导致用户期望与实际不符
- **修复建议**：调整为"高优先级问题 < 72h 响应；普通问题 < 7d 响应"

#### 8.2.10 中等问题 10：R21 性能基准未落实为任务

- **位置**：R21 / tasks.md
- **问题**：R21 缓解措施"P0 启动前先执行基线测量"未落实为 tasks.md P0 任务
- **影响**：可能遗漏基线测量，导致性能基准无法对比
- **修复建议**：在 tasks.md P0 任务前补充"任务 0：P0 前置性能基线建立"

### 8.3 轻微问题（4 项）

#### 8.3.1 轻微问题 1：R26/R27 风险等级调整

- **位置**：§5.2 风险等级矩阵
