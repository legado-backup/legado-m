## 1. Intent（意图）

本 spec 基于 forks-archive-comparison 任务的 v5.0 终版决策结果，对阅读 Archive 私仓的 7 模块深度分析进行整合实施。目标是将 54 项用户价值导向的借鉴决策（B = Borrow）落地为本项目的可交付代码改造，按 P0/P1/P2 三级优先级分阶段实施，最大化用户感知收益，同时控制实施风险与改造成本。

核心目标：
1. 将 14 项 P0 高用户价值借鉴点（用户价值 ≥ 4.5）立即启动，覆盖用户核心场景（搜索/阅读/视频/订阅）
2. 将 19 项 P1 中高收益借鉴点纳入季度规划，覆盖用户中高收益（13 项）+ 开发者侧优化（6 项）
3. 将 21 项 P2 长期优化（含 9 项 UI 优化）纳入年度规划，UI 优化放在最后降低风险
4. 明确不借鉴 64 项决策的边界（含 AI 模块全量否决、BUILD 配置差异、其他低价值项），避免无效改造

## 3. Approach（方案）

### 3.1 选定方案

采用**三阶段渐进式实施**策略，按用户价值与实施成本动态平衡：

**阶段 1（P0，立即启动）**：14 项核心场景优化
- 用户价值区间：4.5 - 5.0
- 实施窗口：按依赖顺序实施（AI 执行，无工期估算）
- 验收要求：每项必须通过真机测试
- 风险控制：每项独立可回退

**阶段 2（P1，季度规划）**：19 项中高收益优化
- 用户中高收益（13 项）：用户价值 4.0 - 4.8
- 开发者侧优化（6 项）：用户价值 2.8 - 4.0（提升开发效率间接惠及用户）
- 实施窗口：按依赖顺序实施（AI 执行，无工期估算）
- 验收要求：模块级集成测试

**阶段 3（P2，年度规划）**：21 项长期优化
- 技术升级类（5 项）：依赖升级、架构演进
- 用户中价值类（7 项）：长期价值改造
- UI 优化类（9 项）：放在最后，降低包体积增长风险
- 实施窗口：按依赖顺序实施（AI 执行，无工期估算）
- 验收要求：完整回归测试

### 3.2 Alternatives Considered

以下备选方案经评估后否决：

1. **一次性全部实施 54 项** → 否决
   - 原因：风险集中、周期过长（>6 个月）、无法快速验证
   - 缺陷：单次回归测试范围过大，问题定位困难

2. **只实施 P0（14 项）** → 否决
   - 原因：用户中高收益项（P1）被遗漏，整体用户价值未最大化
   - 缺陷：未覆盖 RSS/EPUB/VIDEO 模块的中长期优化点

3. **实施所有借鉴项不分优先级** → 否决
   - 原因：无序实施效率低，难以追踪进度
   - 缺陷：低价值项与高价值项混淆，资源浪费

4. **引入 AI 模块（11 项否决项）** → 否决
   - 原因：用户明确反对，需 API key 用户收益小
   - 缺陷：增加包体积与维护成本

5. **不借鉴任何 UI 优化** → 否决
   - 原因：用户反馈 UI 优化可接受增加包体积
   - 缺陷：放弃长期视觉体验提升机会

6. **采用子代理并行实施所有 P0** → 否决
   - 原因：源码文件修改必须串行化（并发文件修改规范）
   - 缺陷：多 Agent 并行 Edit 同一源码文件违反规范

### 3.3 Drawbacks

1. **分阶段实施周期长**：P0 + P1 + P2 三阶段渐进式实施，按依赖顺序推进（AI 执行，无工期估算）
2. **P2 UI 优化增加 APK 体积**：9 项 UI 优化（liquidglass/lottie 等）预计增加 2-5MB
3. **部分借鉴点需要兼容性评估**：如 markwon 3 扩展与现有渲染链兼容性、sora-editor 与现有代码编辑器兼容性
4. **实施过程中可能与现有功能冲突**：如 EpubFile 改造可能与 EPUB 阅读已有逻辑冲突
5. **依赖升级风险**：composeBom 升级、Glide ksp 迁移可能引入兼容性问题
6. **P1/P2 优先级可能随用户反馈调整**：实施过程中需动态重评估

## 5. Scenarios（场景）

### 5.1 S1: 用户搜索订阅内容
- **前置条件**：用户已导入订阅源，订阅源已配置 searchUrl 字段
- **步骤**：
  1. 用户打开订阅页（RssFragment）
  2. 点击搜索入口（REQ-P0-001 新增）
  3. 输入关键词
  4. 系统搜索所有订阅源的内容
  5. 显示搜索结果（按订阅源分组）
  6. 用户点击结果查看详情
- **验收**：用户可搜索订阅内容（REQ-P0-001）
- **性能要求**：搜索响应时间 < 3s

### 5.2 S2: 订阅文章渲染
- **前置条件**：用户打开订阅文章，文章包含 Markdown 格式
- **步骤**：
  1. 文章包含删除线（`~~text~~`）
  2. 文章包含任务列表（`- [x]`）
  3. 文章包含链接
  4. 系统正确渲染这些元素
- **验收**：订阅文章正确渲染（REQ-P0-002）
- **兼容性**：与现有 markwon 核心库兼容

### 5.3 S3: 阅读视觉体验
- **前置条件**：用户打开书籍（任意格式）
- **步骤**：
  1. 用户进入阅读设置
  2. 启用纸墨风格开关
  3. 阅读界面显示纸墨风格
  4. 翻页时纸墨风格保持
- **验收**：纸墨风格生效（REQ-P0-003）
- **性能要求**：FPS ≥ 50

### 5.4 S4: 视频播放加速
- **前置条件**：用户搜索视频书
- **步骤**：
  1. 用户在搜索结果页查看视频书
  2. 系统预加载视频书目录（REQ-P0-004）
  3. 用户点击视频书
  4. 视频快速启动播放（首帧时间下降 ≥ 30%）
- **验收**：视频播放启动速度提升（REQ-P0-004）
- **限制**：预加载不阻塞搜索结果页渲染

### 5.5 S5: RSS 加载加速
- **前置条件**：用户打开 RSS 列表
- **步骤**：
  1. 系统优先从缓存加载（cacheFirst = true）
  2. 后台静默更新内容
  3. 用户感知加载时间 < 500ms
- **验收**：RSS 加载速度提升（REQ-P0-005）
- **可配置**：用户可在设置中关闭

### 5.6 S6: 字体撞色检测
- **前置条件**：用户设置主题配色
- **步骤**：
  1. 用户设置字体颜色
  2. 系统检测与背景/卡片/分隔线的对比度
  3. 如果撞色（对比度低于阈值），提示用户
  4. 用户可选择忽略或调整
- **验收**：撞色检测生效（REQ-P0-006）
- **限制**：不强制阻止用户设置

### 5.7 S7: EPUB 阅读体验
- **前置条件**：用户打开 EPUB 书籍
- **步骤**：
  1. 系统用 spine 优先索引（REQ-P0-009）
  2. 章节加载速度提升（首章加载 < 1s）
  3. 系统过滤非内容资源（REQ-P0-010）
  4. 章节标题归一化
  5. 目录显示规范
- **验收**：EPUB 阅读体验改善（REQ-P0-009, REQ-P0-010）
- **兼容性**：兼容现有 EPUB 文件

### 5.8 S8: 统一源选择
- **前置条件**：用户需要选择书籍源或订阅源
- **步骤**：
  1. 用户触发源选择
  2. 系统弹出 SourceSelectDialog（REQ-P0-007）
  3. 用户可在 book/rss 源间统一选择
  4. 操作步骤减少 ≥ 2 步
- **验收**：源选择操作简化（REQ-P0-007）

### 5.9 S9: 搜索结果合并
- **前置条件**：用户搜索书籍，多源返回结果
- **步骤**：
  1. 用户触发搜索
  2. 系统调用 SearchBookMergeUtils（REQ-P0-008）
  3. 按书名+作者去重
  4. 保留多源信息
  5. 用户统一查看搜索结果
- **验收**：搜索结果合并生效（REQ-P0-008）

### 5.10 S10: P1 综合场景（季度规划）
- **前置条件**：P1 项已实施完成
- **步骤**：
  1. 搜索结果预览覆盖层（REQ-P1-001 RSS-E-05）
  2. 主题预览能力（REQ-P1-002 THEME-E-05）
  3. EPUB 相邻章节预加载（REQ-P1-003 EPUB-E-04）
  4. 书架/源列表拖拽排序（REQ-P1-004 DEPS-B-04）
  5. 字体内嵌支持（REQ-P1-005 EPUB-E-02）
  6. 主题包导入导出（REQ-P1-007/010）
- **验收**：P1 模块级集成测试通过

### 5.11 S11: P2 综合场景（年度规划）
- **前置条件**：P2 项已实施完成
- **步骤**：
  1. 技术升级类完成（composeBom/sora-editor/Glide ksp）
  2. AppearanceKit 套件架构上线
  3. 主题包云端同步可用
  4. UI 优化类完成（液态玻璃/lottie 等）
- **验收**：完整回归测试通过，APK 体积增长 ≤ 5MB
