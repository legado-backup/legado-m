### 1.2 分析方法

**四维度用户价值评分模型**（满分 100 分）：

| 维度 | 权重 | 评分依据 |
|------|------|---------|
| 用户直接感知 | 40% | 用户能否立刻感受到的好处（加载更快、操作更方便） |
| 用户核心场景 | 30% | 是否覆盖阅读 App 核心场景（看书/订阅/视频） |
| 实施成本 vs 用户收益 | 20% | 投入产出比 |
| 用户额外负担 | 10% | 是否需要用户额外配置（如 API key） |

**评分换算公式**：用户价值评分(百分制) = (维度1×0.4 + 维度2×0.3 + 维度3×0.2 + 维度4×0.1) × 20

**辅助分析维度**：
- 依赖关系分析（遗漏/不必要/循环/关键路径）
- 任务合并/拆分建议（功能重叠/工作量失衡）
- 风险等级评估（高/中/低）

### 5.4 关键路径分析（最长依赖链）

经依赖图遍历，识别出以下关键路径：

**最长依赖链 1（3 层）**：
```
THEME-B-06 (P2) → THEME-B-08 (P2) → THEME-E-03 (P2)
```
- AppearanceKit 套件架构 → KitBinding 基础机制 → KitBinding 跨组件绑定
- 总跨度：P2 内部 3 层，均在年度规划窗口内

**最长依赖链 2（3 层）**：
```
BUILD-B-02 (P1) → BUILD-B-06 (P2) → BUILD-B-08 (P2)
```

- 跨 P1/P2，需 P1 完成后才能启动 P2 链路

**最长依赖链 3（2 层，跨 P0/P1）**：
```
EPUB-B-01 (P0) → EPUB-E-04 (P1) 相邻预加载
EPUB-B-01 (P0) → EPUB-B-03 (P1) 性能日志

THEME-B-03 (P1) → THEME-E-04 (P1) 导入导出格式
THEME-B-03 (P1) → THEME-E-02 (P2) 目录化结构
THEME-B-03 (P1) → THEME-B-07 (P2) 云端同步
```

**关键结论**：
- 最长依赖链为 3 层，远低于 5 层警戒线
- EPUB-B-01 是依赖链最长的根节点（3 个直接下游 + 多个间接下游），是 EPUB 模块的关键路径起点
- BUILD-B-02 是 BUILD 模块的关键路径起点，需在 P1 阶段优先完成
