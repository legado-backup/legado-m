## 3. 严重发现（🔴 ADR 间硬矛盾）

### 🔴 发现 #1：ADR-008 与 ADR-002 对 VIDEO-B-02/E-01/E-02 优先级阶段直接矛盾

- **问题描述**：ADR-008 Decision 明确将 VIDEO-B-02/E-01/E-02 标为 P1，但 ADR-002 Decision 将同一批任务升级为 P0，两个 ADR 对同一组任务的优先级阶段判定直接冲突。
- **ADR 编号**：ADR-008 vs ADR-002
- **具体位置**：
  - ADR-008 Decision（design.md 第 222-223 行）："P1：VIDEO-B-02 章节链接缓存+下一集预加载...P1：VIDEO-E-01 ReadRecentBook 写入、VIDEO-E-02 ChoiceSpeedDialog 增强"
  - ADR-002 Decision（design.md 第 109-110 行）："VIDEO-B-02 (预加载集成，v5.1 调整后已升级 P0)...VIDEO-E-01 (ReadRecentBook 写入，v5.1 调整后已升级 P0)...VIDEO-E-02 (ChoiceSpeedDialog 增强，v5.1 调整后已升级 P0)"
- **影响范围**：P0 任务清单（14 项）的合法性、组D 任务调度、VIDEO 模块实施顺序
- **修复建议**：
  1. 更新 ADR-008 Decision，将 VIDEO-B-02/E-01/E-02 从 P1 改为 P0，并添加"v5.1 调整后已升级 P0"标注
  2. 在 ADR-008 Consequences 补充说明升级理由（与本组 P0 共用入口或依赖链）
  3. 在 ADR-008 Alternatives 备选 B 同步更新（原备选 B 提到 VIDEO-B-02/E-01/E-02/E-03 用户价值 4.0-4.8，应明确前 3 项已升 P0）

### 🔴 发现 #2：ADR-001 备选 B 与 ADR-002 P0 项数不一致

- **问题描述**：ADR-001 Alternatives 备选 B 提到"P0 10 项"，但 ADR-002 Decision 已将 P0 范围调整为 14 项，ADR-001 的备选 B 否决理由与当前 P0 范围不符。
- **ADR 编号**：ADR-001 vs ADR-002
- **具体位置**：
  - ADR-001 Alternatives 备选 B（design.md 第 82 行）："备选 B：只实施 P0 10 项 → 否决（遗漏 P1 用户中高收益项，整体用户价值未最大化）"
  - ADR-002 Decision（design.md 第 89 行）："P0 范围调整为 14 项（升级 4 项 P1→P0：RSS-B-05、VIDEO-B-02、VIDEO-E-01、VIDEO-E-02；THEME-B-03 剔除回 P1）"
- **影响范围**：ADR-001 决策依据的准确性、P0 范围演进的可追溯性
- **修复建议**：
  1. 更新 ADR-001 备选 B 为："备选 B：只实施原 P0 10 项 → 部分采纳（v5.1 调整后升级 4 项 P1→P0，P0 扩展为 14 项，详见 ADR-002）"
  2. 或在 ADR-001 添加"v5.1 调整说明"段落，明确 P0 从 10 项扩展为 14 项的演进
  3. 同步检查 ADR-001 Decision 第 74 行"Phase 1 (P0)"描述是否需要补充"14 项"

## 4. 中等发现（🟡 ADR 内部不一致）

### 🟡 发现 #3：ADR-002 标题"分组并行"与内容"物理串行"不一致

- **问题描述**：ADR-002 标题为"P0 阶段分组并行执行"，但 Decision 正文明确说"4 个组按文件隔离原则顺序执行（组间逻辑并行但物理串行，主 Agent 单线程）"，标题与内容语义冲突。同时 Alternatives 备选 A"完全串行执行 P0 任务 → 否决"与 Decision"物理串行"难以区分，备选 A 否决理由不充分。
- **ADR 编号**：ADR-002（内部不一致）
- **具体位置**：
  - 标题（design.md 第 86 行）："ADR-002 P0 阶段分组并行执行"
  - Decision（design.md 第 90 行）："4 个组按文件隔离原则顺序执行（组间逻辑并行但物理串行，主 Agent 单线程）"
  - Alternatives 备选 A（design.md 第 117 行）："完全串行执行 P0 任务 → 否决（无依赖项被人为拉长）"
- **影响范围**：ADR-002 决策可理解性、并行执行策略的可执行性
- **修复建议**：
  1. 将标题改为"ADR-002 P0 阶段分组顺序执行（文件隔离+组内并行）"
  2. 或在 Decision 开头加粗说明"**注意：组间为物理串行执行，非真正并行**"
  3. 更新备选 A 否决理由，明确"完全串行"与"分组顺序执行"的区别（组内独立任务可借用子代理分担分析）

### 🟡 发现 #6：ADR-006 rhino 1.8.1 锁定原因表述与 ADR-022/R29 逻辑链断裂

- **问题描述**：ADR-006 表述"rhino 1.8.1（锁定，minSdk 已提升至 23 但仍低于 24）"容易让人误解为 rhino 1.8.1 在 minSdk 23 下无法运行。实际上锁定原因应是"升级到新版 rhino 需要 API 24+"。ADR-022 保持 minSdk 23 + ADR-006 锁定 rhino 1.8.1 本应是兼容的组合，但 R29 又说要"验证 rhino 1.8.1 在 minSdk 23 下的运行时兼容性"——如果项目已发布，兼容性应该已验证过，R29 的"验证"诉求与 ADR-006 的"锁定"表述存在逻辑断裂。
- **ADR 编号**：ADR-006 vs ADR-022 vs R29
- **具体位置**：
  - ADR-006 Decision（design.md 第 189 行）："rhino 1.8.1（锁定，minSdk 已提升至 23 但仍低于 24）"
  - ADR-022 Decision（design.md 第 487 行）："minSdk 23（Android 6.0，与本项目 app/build.gradle:66 实际一致）"
  - R29（design.md 第 983 行）："Android API 23 最低版本风险（rhino 1.8.1 缺少 Arrays.setAll 需 API 24+）...验证 rhino 1.8.1 在 minSdk 23 下的运行时兼容性"
- **影响范围**：依赖锁定策略的可解释性、minSdk 决策的合理性
- **修复建议**：
  1. 更新 ADR-006 Decision 表述为："rhino 1.8.1（锁定，升级到新版 rhino 需 API 24+ 的 Arrays.setAll，当前 minSdk 23 不满足升级条件）"
  2. 更新 R29 缓解措施为："rhino 1.8.1 已在 minSdk 23 下稳定运行（项目已发布）；风险仅在于未来若需升级 rhino 时需先提升 minSdk 至 24"
  3. 在 ADR-022 Context 补充说明"rhino 1.8.1 与 minSdk 23 兼容性已验证"

### 🟡 发现 #7：ADR-013 与 ADR-002 对 VIDEO-E-01 复杂度评估不一致
