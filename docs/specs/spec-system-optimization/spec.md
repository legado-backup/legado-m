# 规范体系优化需求规格（spec.md）

## Intent（意图）

### 核心问题
当前项目的规范文档体系存在严重的**重复、臃肿、碎片化、失效**问题，导致：
1. AI 加载效率低（重复内容浪费上下文窗口）
2. AI 遵守效率低（同一规则多处出现，不知以哪个为准）
3. 压缩恢复失效（AI 不主动加载项目主规范，项目特定规则被无视）
4. 跨项目复用困难（项目子规范与全局规范边界不清）

### 目标
建立**清晰分层、去重优化、强制加载、可复用**的规范体系结构，让 AI 和其他开发者能够：
- 快速定位适用规则（三层分明）
- 避免规则冲突（单一权威源）
- 压缩恢复后自动加载项目主规范（强制验证）
- 在新项目快速复用规范体系（模板+适配变量）

## Approach（方法）

### Selected Approach（选定方案：三层规范体系结构 + 强制加载机制）

```
第一层：全局通用规范（user_rules/）
  ├─ user_rules.md（基础规则）
  ├─ core-spec.md（核心规范：压缩恢复+输出安全+违禁词规避三道防线+交互+编码哲学）
  └─ danger-ops.md（危险操作安全规则）
        ↓ 压缩恢复时强制加载项目主规范
第二层：项目主规范（AGENTS.md）
  ├─ 项目概述
  ├─ 强制规则（保留流程性核心步骤+触发场景，详细展开移到子规范）
  ├─ 子规范强制加载机制（何时必读+加载后验证）
  ├─ 代码约束摘要
  └─ 快速入口
        ↓ 强制加载机制确保AI必读子规范
第三层：项目子规范（docs/project-rules/）
  └─ 详细规则展开
```

**选定理由**：
1. **单一权威源**：每个规则只在一处详细定义，其他位置只引用
2. **不为缩减而缩减**：AGENTS.md 保留流程性规范的核心步骤和必要强调，只移走"详细展开内容"
3. **强制加载机制**：设计"何时必读+加载后验证"机制，解决"缩减后AI不关注子规范"的历史教训
4. **违禁词三道防线**：预防-检测-恢复，确保AI不被审查中断
5. **跨项目复用**：全局规范层完全通用，新项目只需调整第二层和第三层

### Alternatives Considered（备选方案）

| 方案 | 否决理由 |
|------|---------|
| **方案A：全部集中到全局规范** | 项目特定规则（代码约束/Skill触发）无法通用化，会导致全局规范臃肿且不同项目冲突 |
| **方案B：全部集中到AGENTS.md** | AGENTS.md 会超过1000行，AI 加载效率极低，且压缩恢复后更难完整读取 |
| **方案C：保持现状，只去重** | 不解决"压缩后不加载项目主规范"的核心问题，且碎片化问题依旧 |
| **方案D：用数据库/Wiki管理规范** | AI 无法直接访问，且与现有文件体系不兼容 |

### Drawbacks（已知缺点）

| 缺点 | 接受理由 |
|------|---------|
| AI 需要多加载一层文件（主规范→子规范） | 主规范索引明确指引，加载成本可控；且强制加载机制确保主规范必读 |
| 全局规范变更影响所有项目 | 全局规范变更需谨慎，但变更频率低（行为准则稳定）；项目可覆盖全局规范 |
| 子规范数量增加（新增2个） | 每个子规范职责单一，便于维护；主规范索引清晰，不会迷失 |
| 旧规范引用需全局更新 | 一次性迁移成本，迁移后维护成本降低 |

### Prior Art（参考）

- **OpenSpec 工作流**：已有的"主规范引用子规范"模式（AGENTS.md 引用 openspec-workflow.md）
- **CLAUDE.md / Cursor Rules**：业界 AI 规范文件的分层实践
- **RFC 驱动开发**：Stripe/Uber 的规范分层思想（核心规范+领域规范+实例规范）

### R2: 压缩恢复强制加载机制
- **R2.1** 在 `core-spec.md` 中新增"压缩恢复后强制加载项目主规范"章节
- **R2.2** 要求压缩恢复后输出"已加载项目主规范：{路径}"+ "已识别的强制规则：{清单}"
- **R2.3** 列出反模式（不读取/部分读取/依赖印象）

### R2B: 违禁词规避三道防线（新增，用户重点强调，范围覆盖所有违禁类别）
- **R2B.1** **预防防线**：在 `core-spec.md` 中强化输出前自检清单，覆盖**所有可能触发审查的内容类别**（不仅限于视频网站）：
  - 成人/色情内容（成人网站、性暗示、裸露描述等）
  - 违法内容（赌博、毒品、诈骗、黑客攻击方法等）
  - 政治敏感内容
  - 暴力/恐怖主义内容
  - 视频/影视/流媒体网站域名和URL（已验证高危场景）
  - 其他可能触发审查的敏感关键词
- **R2B.2** **检测防线**：设计"内部过滤再输出"机制，AI 输出前必须在内部完成过滤：
  - 敏感域名/URL → 代号替换（站点A/B/C）或路径模式化（`/path/{id}`）
  - 敏感字段（token/cookie/password/key/secret/auth/credential）→ 完全隐藏 `***`
  - 敏感内容描述 → 只保留技术结构（线路数/集数/DOM选择器/路径格式）
  - 原始日志/HTML全文 → 提取关键技术信息后输出
  - 禁止直接输出任何可能触发审查的原始内容
- **R2B.3** **恢复防线**：设计"被审查中断后自动恢复"机制，AI 被中断后立即继续未完成工作，不停顿不等待用户催促
- **R2B.4** 提供"违禁词规避场景速查表"，覆盖所有高危场景类别（成人/违法/政治/暴力/视频网站/日志分析/URL输出/HTTP头/错误信息/配置文件）
- **R2B.5** 明确"技术分析优先"原则：用户要求技术分析时只输出异常类型/错误码/调用栈/技术结论/修复方案
- **R2B.6** 设计"不确定默认过滤"原则：AI 不确定某内容是否触发审查时，默认过滤或用技术性描述替代

### R2C: 子规范强制加载机制（新增，解决历史教训）
- **R2C.1** AGENTS.md 中每个强制规则不仅给出子规范路径，必须明确"触发场景"和"必须加载的时机"
- **R2C.2** 设计"子规范加载验证"机制：AI 加载子规范后必须在输出中体现（如引用子规范的具体条款）
- **R2C.3** AGENTS.md 保留流程性规范的核心步骤（如 OpenSpec 的8步流程概要、E2E测试的5.5.1-5.5.8 步骤名），AI 看到核心步骤即知需加载子规范获取详细内容
- **R2C.4** 禁止"只移不引"：移到子规范的内容，主规范必须有明确的"详见 [子规范]"引用

### R6: 验证策略（新增，用户重点强调"如何真实验证"）

> **核心挑战**：当前对话已加载旧规范（系统注入固定），新规范需新对话才能加载。验证必须分三层设计。

- **R6.1** **文件层验证（当前对话可执行）**：
  - 验证全局规范文件正确创建（core-spec.md / danger-ops.md / user_rules.md）
  - 验证旧文件已删除（rule-*.md 系列）
  - 验证 AGENTS.md 修改正确（保留核心步骤+引用子规范）
  - 验证子规范文件正确创建/删除（version-delivery-sync.md / complex-task-pipeline.md / ai-context-recovery-and-safety-spec.md 删除）
  - 验证方法：Read/Grep/Glob 工具检查文件存在性和内容完整性

- **R6.2** **加载层验证（需新对话执行）**：
  - 验证全局规范被平台自动加载（新对话开始时，AI 能引用 core-spec.md 内容）
  - 验证 AGENTS.md 被正确注入（新对话开始时，AI 能引用 AGENTS.md 修改后的内容）
  - 验证方法：用户启动新对话，要求 AI 输出已加载的规范清单

- **R6.3** **行为层验证（需实际任务执行）**：
  - **压缩恢复验证**：触发上下文压缩，验证 AI 是否输出"已加载项目主规范"+ "已识别的强制规则清单"
  - **违禁词规避验证**：在实际任务中测试 AI 是否遵守三道防线（如分析含敏感内容的网站时，AI 是否用代号替代）
  - **子规范强制加载验证**：触发特定场景（如 OpenSpec 任务），验证 AI 是否加载对应子规范并在输出中体现
  - 验证方法：在实际开发任务中观察 AI 行为

- **R6.4** **验证文档**：在 design.md 中提供"三阶段验证清单"，明确每阶段的验证项、验证方法和预期结果

## Scenarios（场景）

### 场景1：正常开发任务（AI 首次加载）
```
1. 用户启动对话，全局规范（core-spec.md等）自动加载
2. 用户提问"帮我优化视频播放器"
3. AI 识别触发场景"代码优化"，根据 core-spec.md 加载项目 AGENTS.md
4. AGENTS.md 索引表指引"代码优化→logging-during-refactoring.md"
5. AI 加载对应子规范，按规则执行
```

### 场景2：上下文压缩恢复
```
1. 上下文压缩触发
2. AI 按全局规范 core-spec.md 读取四件套
3. AI 必须完整读取 AGENTS.md，输出"已加载项目主规范"+ "已识别的强制规则清单"
4. AI 声明"以上规则将在本次会话中严格遵守"
5. 从 TaskList 恢复任务，遵守已识别的规则
```

### 场景3：新项目复用规范体系
```
1. 用户在新项目启动对话
2. 全局规范 core-spec.md 自动加载（跨项目通用）
3. 用户参考"新项目AGENTS.md模板"创建项目主规范
4. 用户参考"适配变量说明"调整路径
5. 用户参考"项目记忆初始化模板"创建 project_memory.md
6. 新项目规范体系就绪
```

### 场景4：规则冲突处理
```
1. AI 发现全局规范与项目 AGENTS.md 规则冲突
2. 按 core-spec.md §3.2 规则：项目 AGENTS.md 优先（项目特定优先）
3. AI 在输出中说明冲突点和采用的规则
4. 继续执行任务
```

### 场景5：异常 - 压缩后未加载项目主规范
```
1. 上下文压缩触发
2. AI 只读取 TaskList 和 project_memory.md，未读取 AGENTS.md
3. AI 输出中缺少"已加载项目主规范"声明
4. 用户发现后提醒"请加载项目主规范"
5. AI 立即读取 AGENTS.md，输出强制规则清单
6. 继续任务
```
