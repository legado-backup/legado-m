# spec：导入源质量过滤与公共源质量校验组件

## Intent

将书源/订阅源质量校验抽象为**公共组件**（单源探测核心 + 形态适配评分），统一服务两大场景：①导入书源/订阅源时自动过滤低质量源（默认关闭，复核窗口零静默误伤）②库内存量源批量体检，快速筛选低分/存疑源并辅助批量删除或禁用。评分算法 v2 基于解析原理与调试原理实证重设计，消除形态歧视与系统性误判。

## Scope

### 做什么

**公共组件（核心交付）**
- `SourceQualityChecker`：suspend 单源校验器，从 CheckSourceService 剥离纯探测逻辑（域名探测/搜索/发现/详情/目录/正文/列表/分类），**零写库副作用**，产出 `SourceQualityReport`
- 评分算法 v2：按源形态分维度模板（书源 5 类型 × 入口形态；订阅源 3 类型 × 入口形态），"已校验维度归一化"计分，区分 不适用/未校验/失败 三态，存疑源（登录/jsLib/源变量/webView 依赖）打 suspect 标志

**场景 1：导入过滤**
- 书源管理/订阅源管理右上角菜单"导入校验设置"，总开关默认关
- L1 静态结构检查（0 网络成本）+ 勾选导入后 L2/L3 联网校验 + 三档严格度判定 + FILTERED 复核窗口（可恢复）+ 实时进度可取消 + 千条集合性能设计

**场景 2：存量源质量体检**
- 书源管理/订阅源管理菜单"质量体检"入口：选择范围（选中源/分组/全部）→ 公共组件批量校验（并发/进度/取消同导入场景）→ 体检结果页（得分排序 + 状态筛选：低分/失效/存疑）→ 多选删除或禁用（用户显式确认，体检过程本身不写库）

### 不做什么

- 不迁移/重构现有 CheckSourceService/CheckRssSourceService（保持稳定交付行为，仅底层探测函数改为调用公共组件，后续迭代再整体迁移）
- 不做规则内容质量智能评分（只验可用性）
- 不改变关闭导入校验开关时的现有导入行为
- 不做静默过滤与静默删除（导入有复核窗口，体检删除需显式确认）
- 不引入数据库迁移、不新增 Room 表（体检结果为内存态 + 会话级缓存）

## Approach

### Selected Approach

**公共组件分层 + 形态模板评分 v2 + 确定性证据过滤**：

1. **分层**：探测核心（纯 suspend 函数，无副作用）→ 评分层（形态模板归一化）→ 判定/消费层（导入=档位证据判定；体检=排序筛选展示；现有校验服务=分组+weight 写库）。剥离清单实证自 CheckSourceService：checkBook L379 / isDomainReachable L166 / checkDomainReachable L184 / 异常分类 L144-161 / doCheckRssSource L203-359 均可平移为返回 Report 形态。

2. **评分 v2 关键修正**（对照现有 SourceWeightCalculator 缺陷）：
   - **形态模板**：书源按 bookSourceType（文本/音频/图片/文件/视频）+ 入口（搜索/发现）选用维度集；file 型不含详情/目录/正文，video 型不含详情；订阅源按 type + 入口形态，startHtml webview 型用"首屏渲染"维度，ruleArticles 空合法（默认 XML 规则）
   - **归一化口径**：得分 = Σ通过维度权重 / Σ已校验适用维度权重 × 100，并展示覆盖度（已校验/适用总维度数）——消除"未校验计满分"虚高
   - **三态区分**：Pass / Fail / NotApplicable（不计分）/ NotChecked（不计分）；"字段缺失跳过"不再伪装成满分
   - **suspect 存疑机制**：检测到 登录依赖（loginCheckJs/loginUi）/ jsLib 依赖 / 源变量（`{{source.getVariable()}}`）依赖 / useWebView 型 时，报告 suspect=true 并标注原因——此类源探测失败不作为确定性失败证据（导入宽松/标准档一律放行），体检结果页提示"需人工确认"

3. **导入过滤判定**（沿用电表：宽松/标准/严格三档，判定基于证据而非分数）：
   - 宽松（默认）：仅滤 结构残缺 / 域名不可达 / 换词重试后仍解析 0 结果；suspect 源强制存疑放行
   - 标准：+ 搜索/列表失败（含重试后异常，suspect 除外）
   - 严格：+ 发现/目录/正文失败

4. **校验时机**（导入场景）：L1 解析后同步执行；L2/L3 在勾选导入后、落库前执行，列表秒出不阻塞

### Alternatives Considered

| 备选方案 | 否决理由 |
|---------|---------|
| 沿用 SourceWeightCalculator 原分值不改动 | 实证存在形态歧视（file/video 无目录正文维度、纯发现源被搜索惩罚、RSS webview 型虚高）与系统性误判（源变量/登录/jsLib），分数不可比 |
| 纯分数阈值过滤 | 语义不透明；网络偶发超时即误伤；suspect 源无法用分数表达 |
| 结果列表展示前完成全部联网校验 | 千条集合列表被阻塞数分钟 |
| 静默过滤 + toast | 违背"严禁误伤"硬约束 |
| 本期整体迁移 CheckSourceService 到公共组件 | 已稳定交付功能整体迁移回归风险大；本次抽公共探测核心即可统一逻辑，迁移留后续迭代 |
| 体检写回"失效"分组沿用现有机制 | 与导入场景需求无关且自动写库违背"体检只读+显式删除"原则；现有分组机制保留在旧校验功能内不动 |

### Drawbacks

- **缺陷**：宽松档无法识别"域名可达但规则全坏"源（搜索成功但目录/正文烂）→ 兜底：严格档 + L3；体检场景可深度校验识别此类源
- **风险**：suspect 判定过宽会大量放行低质量源 → 兜底：suspect 仅对四类可实证依赖打标；体检结果页单独列出 suspect 源供人工处理
- **风险**：千条集合联网校验耗时（8 并发 × 10s 超时最坏 ~25 分钟）→ 兜底：进度实时 + 可取消 + L1 先行拦截 + host 域名缓存 + 同 host 试采限额
- **风险**：video/file 形态模板的探测深度有限（文件型不验证真实下载链路）→ 接受理由：导入/体检场景目标是"筛掉明显失效源"而非 100% 保真，深度使用时用户自会调试
- 双机制并存期（旧校验服务 + 新公共组件）存在代码重叠 → 接受理由：底层探测核心已统一（服务调用组件），UI/写库分层差异是有意设计

## Requirements

### Requirement: 公共校验组件 SourceQualityChecker

- `suspend checkBookSource(source, options): SourceQualityReport` / `checkRssSource(source, options)`
- options：并发数、单源超时、重试开关、校验深度（快速/深度）、关键词
- 内置：host 级域名探测缓存、同 URL 去重、同 host 试采限额（防请求风暴）、Semaphore 限流
- 零写库副作用：返回 Report，落库与否由调用方决定
- 网络调用点可注入替换支撑单测

### Requirement: 评分算法 v2（形态模板 + 归一化）

- 书源按 bookSourceType × 入口形态、订阅源按 type × 入口形态选用维度模板（不适用维度不计分）
- 得分 = Σ通过权重 / Σ已校验适用权重 × 100，报告含覆盖度
- 三态：Pass/Fail/NotApplicable/NotChecked；"字段缺失跳过"= NotApplicable 而非满分
- suspect 标志五类：登录依赖/jsLib 依赖/源变量依赖/useWebView 型/**内网地址**（字面回环/私有/169.254 网段，跳过联网探测防内网扫描但不误杀局域网源），附原因说明
- 保留与 SourceWeightCalculator 的映射（体检若需写回 weight 场景可用）

### Requirement: 导入校验开关与设置入口

书源/订阅源管理右上角菜单"导入校验设置"弹框（P1 收敛：主界面仅 3 项）：

- **总开关**（默认关）
- **校验深度**三选一：仅结构（L1，秒级不联网）/ 快速（L2，默认）/ 深度（L3）
- **严格度**三选一（宽松默认），每档附白话说明（"宽松：只滤打不开的源（推荐）/标准：还会滤搜索失败的/严格：目录正文有问题也滤"，P6）
- **高级设置折叠区**：并发数（默认 8）、单源超时（默认 10s）、重试开关（默认开）
- 导入弹框内提供"导入校验"快捷开关（引用同一配置，P1 入口错位修正）
- 勾选源数量超过阈值（如 100）时，导入确认提示"建议切换快速/仅结构模式"（四方审查争点1）
- CacheManager 持久化，两管理页共用

### Requirement: L1 静态结构检查（导入解析后即时）

- 书源：`bookSourceUrl` 空，或（searchUrl 空且非 enabledExplore）→ 结构残缺；file/video 型仅要求 bookSourceUrl + 搜索或发现入口存在
- 订阅源：`sourceUrl` 空 → 结构残缺；列表规则缺失**不**判残缺（默认 XML/webview 型合法）
- 结构残缺 = 确定性失败，列表 FILTERED 态即时标记

### Requirement: L2 快速联网校验（勾选导入后、落库前）

- **联网校验启动前全局连通性预检**（四方审查攻击6+v4 二轮修正）：双信源预检 = 系统网络状态（ConnectivityManager）+ 实测探针（国内外高可用地址各一，任一可达即网络正常）——仅信系统状态会被 captive portal 误报"有网"导致域名探测全失败→"域名不可达"全量误滤；探测异常（确认断网/探针全不可达）则全部源标"未测+存疑"放行并 toast 告知"网络异常，N 条未校验"
- 书源：域名探测 → searchBookAwait 试搜（失败且重试开启则换词重试 1 次）；enabledExplore 源追加发现试采
- 订阅源：域名探测 → 首入口试采列表（文章数 > 0 即成功）；webview 型源按首屏渲染探测
- 单源硬超时；超时/网络异常 = 存疑非失效
- 每源产出 SourceQualityReport（得分/维度明细/suspect/失败原因/是否确定性失败）
- **结论缓存复用**（四方审查攻击7+v4 二轮修正）：同 URL 且 lastUpdateTime 未变时复用缓存结论（CacheManager，TTL 24h），重复导入同集合不全量重测；**缓存键含 严格度档位+校验深度+schemaVersion**，档位/深度不匹配或版本不符则重测（防 L2 结论被严格档误用、防评分算法演进后旧缓存反序列化异常）

### Requirement: L3 深度校验（可选）

L2 基础上追加：试搜首结果 → 详情 → 目录 → 正文试读；失败计入对应维度（严格档过滤证据）。

### Requirement: 确定性失败判定与存疑放行

- 过滤证据仅限：L1 结构残缺、域名不可达（双探测均失败）、重试后解析明确 0 结果、（标准/严格）搜索/列表失败、（严格）发现/目录/正文失败
- suspect 源在宽松/标准档强制存疑放行；严格档仅按用户显式选择处理
- 得分仅作展示参考，判定不依赖分数

### Requirement: 过滤复核窗口（零静默误伤）

被过滤源呈 FILTERED 态：展示源名、**白话原因**（如"网址打不开/搜索不到结果/规则残缺"）、得分；默认不落库（P3 防橡皮图章）：

- 逐条勾选恢复；**全选恢复需二次确认**（防止用户无脑全导）
- 恢复方式两种：正常导入 / **仍要导入（导入后自动禁用）**（P8 置灰期望，复用禁用态）
- 提供"复制被过滤源列表"兜底（JSON 到剪贴板），关窗后仍可找回
- 落库后 toast 汇总"导入 N 条，过滤 M 条"，并提示"重新导入同一集合可更新旧源"（P9）

### Requirement: 进度与取消

L2/L3/体检校验期间展示实时进度（已校验/总数/已过滤数）；导入场景（P2 防全损 + v4 二轮 ProcessDeath 补强）：

- 校验中按返回键**弹确认**，不直接丢弃
- 确认框提供两种退出：直接取消（本次导入终止，无源落库，整批原子性）/ **停止校验并导入已通过源**（半程落库）
- **长集合分批落库**：勾选源 > 200 时自动切换分批落库（每 50 条一批），进度条标注"已导入 X 条"；进程被杀后已落库部分保留（不再要求重导全量）
- 体检场景：应用级会话，页面退出不中断

### Requirement: 千条集合性能与稳定

Semaphore（默认 8）+ host 域名缓存 + 同 URL 去重 + 同 host 试采限额 + 单源硬超时 + 流式聚合 + 不阻塞主线程。

### Requirement: 存量源质量体检

- 入口：书源/订阅源管理菜单"质量体检"（与现有"校验"入口命名差异化，P7）；范围选择（选中源/当前分组/全部）
- 批量校验复用公共组件（并发/进度/取消同导入）；**体检过程不写库**
- 体检会话为应用级单例（QualityCheckSession，**按源类型分书源/订阅源两个独立会话**，A5）：校验进行中用户离开页面不中断，可重进查看；新体检覆盖同类型上一轮（先 cancel 旧 Job 再清结果）
- 体检结果页：**用户层四态白话标签**（可用/失效/存疑/未测，P5；"失效"=存在 Fail 证据；"存疑"=suspect；"未测"=适用维度未校验；"低分"筛选口径=无 Fail 证据但 score<60）+ 得分/覆盖度收进单源详情
- 多选删除/禁用（**禁用为主按钮**，P4）：批量删除前**自动导出所选源 JSON 备份**到用户目录并在确认框明示备份路径（S6 误删兜底）；删除后列表即时刷新
- 结果页多选底栏对齐管理族规范（全选/反选+操作按钮，用户既有硬约束）

### Requirement: 与现有功能共存

- 现有校验功能（CheckSourceService/分组/weight 排序）行为不变，底层探测函数改为调用公共组件（等价重构，行为回归验证）
- "质量体检"与"校验"入口命名差异化，体检首次打开弹一句话分工说明（体检=只读评分+批量清理；校验=标注分组+权重，P7）
- 导入链路共存：L1 结构残缺源（FILTERED）不参与对比标记（NEW/UPDATE/EXIST 判定无意义）；EXIST 状态源默认不勾选不校验（现有行为），**"全选"属用户显式行为、含 EXIST，勾选的 EXIST 纳入校验**，手动勾选或全选后判定规则均与 NEW 一致（四方审查攻击8+v4 二轮）；导入校验与 18+ 过滤正交，18+ 先行；保留名称/分组/启用状态等导入选项不受影响

## Scenarios

### Scenario: 公共组件三场景分流

- **WHEN** 分别执行 导入过滤 / 存量体检 / 现有批量校验
- **THEN** 三者调用同一 SourceQualityChecker 单源探测核心；导入不入库、体检不写库、现有服务按原逻辑写分组+weight

### Scenario: file 型书源不被维度歧视

- **WHEN** 校验 bookSourceType=3 的书源（无目录/正文规则，合法）
- **THEN** 评分按 file 模板（域名+搜索或发现），目录/正文=NotApplicable 不计分，可得满分；不产生"目录失效"误判

### Scenario: RSS webview 型源

- **WHEN** 校验 startHtml 型订阅源（宽松档）
- **THEN** L1 不判残缺；列表探测走首屏渲染或存疑放行；不产生"列表失效"误判

### Scenario: 源变量依赖源不被误杀

- **WHEN** 书源 searchUrl 含 `{{source.getVariable()}}` 且库内无变量，试搜 0 结果
- **THEN** Report suspect=true（原因=源变量依赖），宽松/标准档导入放行；体检结果页归入"存疑"组提示人工确认

### Scenario: 登录源不被误杀

- **WHEN** 配置 loginCheckJs 的书源未登录状态下校验失败
- **THEN** suspect=true（原因=登录依赖），同上处理

### Scenario: 默认关闭不改变现有行为

- **WHEN** 导入校验开关关闭，导入任意集合
- **THEN** 流程与现状完全一致

### Scenario: 宽松档导入混合集合

- **WHEN** 校验开启（宽松档），导入含 ①正常 ②结构残缺 ③域名失效 ④临时 5xx ⑤suspect 源的集合并勾选导入
- **THEN** ②③进 FILTERED；①④⑤落库；toast"导入 3 条，过滤 2 条"可复核恢复

### Scenario: 搜索换词重试

- **WHEN** 首搜解析 0 结果且重试开启
- **THEN** 换词重试 1 次，成功放行；仍 0 结果才确定性失败

### Scenario: 千条集合导入

- **WHEN** 导入千条级集合并全选
- **THEN** 并发≤配置值、host 缓存+试采限额生效、进度实时、可取消、不崩溃

### Scenario: 校验中取消

- **WHEN** L2 校验中关闭导入弹框
- **THEN** 协程全取消，本次导入终止，无源落库

### Scenario: 复核恢复

- **WHEN** 用户在复核窗口勾选 FILTERED 源点"仍要导入"
- **THEN** 该源随本批落库

### Scenario: 存量体检筛选删除

- **WHEN** 用户对全部书源执行体检（深度），完成后按"失效"筛选并多选 5 条删除
- **THEN** 体检期间无任何写库；二次确认后 5 条删除；结果页分数与各源实测一致且排序正确

### Scenario: 断网导入不全量误滤

- **WHEN** 飞行模式/断网状态下开启校验（快速档）导入本地 JSON 集合
- **THEN** 联网预检确认断网后，全部源标"未测+存疑"放行正常落库，无源被误滤（宽松/标准/严格档一致），toast 告知"网络异常，N 条未校验"

### Scenario: 网络正常时不误触发短路

- **WHEN** 网络正常（仅个别源站失效）导入含大量死源的集合
- **THEN** 双信源预检确认网络正常，不触发短路；死源按判定规则正常过滤（反向用例，v4 二轮补）

### Scenario: 重复导入复用缓存结论

- **WHEN** 同一集合 24h 内第二次导入，源 lastUpdateTime 未变
- **THEN** 直接复用上次校验结论（不重测），过滤/放行判定与上次一致；源更新后重新校验

### Scenario: EXIST 源校验范围

- **WHEN** 导入集合中含库内已存在且未更新的源（EXIST 态）
- **THEN** 默认不勾选不校验；用户手动勾选后纳入校验且判定与 NEW 一致；L1 残缺源不参与 NEW/UPDATE/EXIST 对比标记

### Scenario: 现有校验功能行为不变

- **WHEN** 用户使用现有"校验"按钮批量校验（底层已切换公共组件探测核心）
- **THEN** 分组标注/weight 回填/respondTime 行为与重构前一致（回归验证项）
