**结论：P0-5 和 P0-6 必须全量回归，其余可抽样回归。**

| 优化项 | 全量回归必要性 | 原因 |
|--------|--------------|------|
| P0-5 | ✅ 必须 | 影响"所有 HTTP API"，单点故障波及全局 |
| P0-6 | ✅ 必须 | 影响 50+ 调用点，每点都可能引入回归 |
| P0-1 | ⚠️ 抽样 | 影响目录更新+缓存下载两个流程 |
| P0-2 | ⚠️ 抽样 | 仅影响 upTocPool 重建路径 |
| P0-3 | ⚠️ 抽样 | 仅影响 CacheBookService 销毁路径 |
| P0-4 | ⚠️ 抽样 | 仅影响书源校验流程 |

## 九、审查结论

### 9.1 总体结论

**审查报告（audit-report.md）从静态代码审查角度质量较高**（13 项配置点全覆盖、35 项建议分级清晰、量化分析到位），**但从测试验证角度存在严重缺口**：

- 6 项 P0 优化**全部无测试用例**
- 8 项重点 P1 优化**全部无量化验证方法**
- 0 项优化有**低端机型真机测试方案**
- 0 项优化有**并发场景测试设计**
- 现有 `verify_thread_pool_split.py` **覆盖范围错位**（验证 UI 配置，不验证运行时行为）

### 9.2 实施前必须补齐的测试方案

**强烈建议在实施任何 P0 优化前，先完成以下测试方案补齐**：

1. **新增 8 个测试脚本**（参考第六章 6.2 节）
2. **设计 28 个 P0 测试用例**（参考第四章）
3. **设计真机测试矩阵**（低端/高端 + WiFi/4G 切换）
4. **扩展 fixed_test_workflow.md**（线程池测试章节）
5. **建立量化验证基线**（before 指标采集）

### 9.3 风险提示

**若不补齐测试方案直接实施 P0 优化**，存在以下风险：

| 风险 | 影响 |
|------|------|
| 改了不知对错 | 优化效果无法量化验证，可能引入新问题未发现 |
| 并发问题难复现 | 无并发测试用例，运行时问题难以触发和定位 |
| 低端机型崩溃 | 无低端机型测试，可能引入 OOM/ANR |
| API 回归范围不清 | P0-5 影响所有 API，无清单可能遗漏 |
| 50+ 调用点遗漏 | P0-6 改造无系统回归，可能漏改或错改 |
