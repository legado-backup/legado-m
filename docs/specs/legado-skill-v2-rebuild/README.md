# Legado Skill V2 重建方案

> **状态**：设计中 | **创建日期**：2026-06-22 | **基于**：第十轮深度审查 + 全量实现差距分析

## 1. 项目背景与终极目标

### 1.1 项目背景

Legado（阅读M）书源/订阅源智能创建器（legado-source-creator）的全面重建方案。基于对现有 Skill 的设计文档、落地实现、组件能力与测试体系的深度审计，输出对齐现有 Skill 架构的新版统一 OpenSpec 优化设计文档。

Skill 用于支撑 AI/Agent 完成书源、订阅源的生成、优化、调试、验证全流程服务。

### 1.2 终极目标

让 AI/Agent 使用 legado-source-creator Skill 时，能够通过"经验大脑 + 测试双手 + 仿真底座"三件套，端到端完成书源订阅源的创建、优化、测试、进化，减少对开源阅读源码的依赖：

1. 通过经验教训快速理解如何创建/优化书源订阅源
2. 用 Python 客户端和 JAR 仿真服务端对输出的书源订阅源快速测试
3. 测试结果与真机开源阅读无差异化
4. 通过测试结果快速优化修复，并落地进化经验教训

### 1.3 合规声明

> **所有开发与测试必须遵守著作权法律法规，仅可使用合法授权的内容源。** 测试样本选取合法合规、真机可正常运行的真实书源/订阅源，不得用于侵犯他人著作权的行为。

## 3. 前序方案问题诊断

### V1 方案的 7 大根本问题

| # | 问题 | 根因 | 后果 |
|---|------|------|------|
| **P1** | 170+ 子任务仅完成 15 个（8.8%） | 懒原则滥用，将"减少过度工程"曲解为"跳过必要实现" | 设计文档与实现严重脱节 |
| **P2** | 回避真实书源订阅源测试 | 挑最简单的源测试，回避复杂源 | JAR 仿真端无法支持真机可运行的源 |
| **P3** | 未校验子代理输出 | 信任子代理返回结果，不交叉验证 | 错误/空壳实现被标记为"已完成" |
| **P4** | 实施决策与设计文档不同步 | 实施时做出 AD-01~AD-12 决策，未同步到设计文档 | 文档失去参考价值 |
| **P5** | Python 客户端非工程化 | 无虚拟环境、无层级设计、双客户端并存 | 无法可靠运行和维护 |
| **P6** | JAR 仿真端与真机源码差距大 | 未逐行对比源码就动手实现 | 7 个高风险 bug、OkHttp 版本不一致 |
| **P7** | 经验闭环断裂 | write_to_basic_memory() 返回 MCP 指令但无人消费 | 经验无法反哺 |

### 自我反省：实施中的偷懒/错误决策

| 决策 | 当初理由 | 实际后果 | 反省 |
|------|---------|---------|------|
| AD-10: 只修复 P0 级差异 | "懒原则，优先级" | 大量 P1 差异未修复，真机源运行失败 | P1 差异对真实源有实际影响，不应跳过 |
| apply_auto_fix() 仅处理 relative_url | "简化说明" | auto_fixer.py 的完整修复能力未被主流程调用 | 应直接调用 auto_fixer.auto_fix_error() |
| verify_fix() 仅验证 JVM ping | "简化说明" | 修复后验证环节空转 | 应执行实际规则验证 |
| 3 个外部模块不存在不处理 | "try/except 降级" | cookie_manager/smart_http_client/knowledge_matcher 永远不可用 | 要么实现，要么移除导入代码 |
| 回避复杂书源测试 | "找最简单的源测试" | JAR 仿真端无法支持真机可运行的源 | 必须用真实复杂源做端到端测试 |
| OkHttp 5.x vs 4.x 版本差异 | "新版本更好" | 网络行为与真机不一致 | 应与真机版本锁定 |

## 4. V2 方案核心设计原则

1. **真机兼容优先**：所有书源订阅源必须在 JAR 仿真端 100% 兼容运行
2. **源码驱动实现**：先看源码逻辑再动手，不臆测
3. **真实源测试验证**：每项实现必须用真实书源订阅源各 50+ 做端到端测试
4. **工程化交付**：Python 客户端使用虚拟环境、层级设计、单入口
5. **单 JAR 架构**：仿真服务端合并为单个 JAR 文件
6. **闭环验证**：子代理输出必须交叉验证，不信任单一来源

## 7. 与 V1 方案的关系

V1 方案（legado-skill-optimization）中的已完成任务（15 项）作为本方案的基础，未完成任务重新评估优先级后纳入本方案。V1 的 185 个 GAP 项重新分类，去除过度修复项（75 个），保留必需修复项（52 个）和可选修复项（28 个）。

**V2 相对 V1 的核心变化**：
- 修正 OkHttp 版本认知（4.x → 5.3.2，与真机一致）
- 引入前置核查结论（7 大项）作为设计基线
- 强化强制验证闭环要求（50+ 真实源端到端测试）
- 重定义懒原则边界，禁止以"简化"为由跳过必要实现
- 子代理输出强制交叉验证
