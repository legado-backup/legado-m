# 规范体系优化（spec-system-optimization）

> **状态**：✅ 设计完成 → 🔄 开发中
> **创建时间**：2026-07-12
> **任务类型**：文档重构 + 规范体系优化

## 功能概述

对当前项目的规范文档体系进行深度优化，建立**三层规范体系结构**（全局通用规范 → 项目主规范 → 项目子规范），解决以下核心问题：

1. **重复内容泛滥**：上下文压缩恢复机制、输出安全规范、AskUserQuestion 交互规则等在全局规范、项目主规范、项目记忆中多处重复
2. **AGENTS.md 臃肿**：400+ 行，7个强制规则全部详细展开，AI 加载和遵守效率低
3. **全局规范碎片化**：8个分散文件，缺乏统一组织
4. **压缩恢复失效**：AI 压缩后不主动加载项目主规范，项目特定规则被无视
5. **跨项目复用困难**：项目子规范与全局规范边界不清，难以在新项目复用

## 核心能力

- 建立**三层规范体系**：全局通用 → 项目主规范 → 项目子规范
- **AGENTS.md 瘦身**：从 400+ 行精简至 ≤200 行，详细规则移到子规范
- **全局规范整合**：8个碎片文件整合为 3个模块化文件
- **压缩恢复强化**：全局规范增加"强制加载项目主规范"条款+验证机制
- **去重清理**：删除与全局规范100%重复的项目子规范
- **跨项目复用**：提供新项目初始化模板和适配变量说明

## 核心设计决策

1. **三层分离**：全局规范管"AI行为通用准则"，项目主规范管"项目核心步骤+触发场景+子规范引用"，子规范管"详细规则展开"
2. **不为缩减而缩减**：AGENTS.md 保留流程性规范的核心步骤（如 OpenSpec 8步流程名、E2E 5.5.1-5.5.8 步骤名），只移走"详细展开内容"到子规范
3. **子规范强制加载机制**：每个子规范引用明确"何时必须加载"+ "加载后验证"，解决"缩减后AI不关注子规范"的历史教训
4. **违禁词规避三道防线**：预防（覆盖所有违禁类别：成人/违法/政治/暴力/视频网站等+自检）→ 检测（内部过滤再输出）→ 恢复（中断后自动恢复），确保AI不被审查中断
5. **全局规范强制加载项目主规范**：压缩恢复后必须输出"已加载项目主规范"+ "已识别的强制规则清单"
6. **去重优先**：删除 `ai-context-recovery-and-safety-spec.md`（与全局规范100%重复）
7. **三阶段验证策略**：文件层验证（当前对话）→ 加载层验证（新对话）→ 行为层验证（实际任务），解决"如何真实验证规范有效"问题
