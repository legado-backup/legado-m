# Rhino 引擎升级方案（语法兼容 + 性能）

> 状态：✅ 已完成（**最终决策 = 路径 B：保持 1.8.1 锁定**，沉淀"待抬 minSdk 直跳 1.9.1"里程碑）

## 功能概述

深度分析 Legado 项目中自定义 JS 引擎依赖 `org.mozilla:rhino`（当前锁定 **1.8.1**）的升级潜力，从**语法兼容性**角度评估「哪个最新 jar 能替换当前版本」，目标是在**不破坏现有用户编写书源/订阅源语法**的前提下**加快解析性能**。

核心矛盾：最新版 Rhino 1.9.1（2026-02 发布）的 ES6 支持是 1.8.1 的超集且带来 10-30% 解释器性能提升，但其新增实现对 `VarHandle` 的引用带来 Android API 33 以下兼容问题。**2026-08-03 实证已澄清本质**：运行时探针证实 `SlotMapOwner$ThreadedAccess`（唯一 VarHandle 类）在项目配置（feature17=false）下**永不加载**、26/26 书源片段全部通过，运行时对 API<33 安全；真正的唯一剩余障碍是**构建期 D8 反糖化**（desugar 不覆盖 `VarHandle`），需以 Spike（`assembleDebug`）实测定位。本 spec 产出**选型决策 + 可行性验证 Spike**，为是否/如何升级提供数据支撑。

## 核心能力

- 📊 **候选引擎横评**：Rhino 1.9.1 / 1.8.0 / 1.7.15.1 / QuickJS / Graal.js 语法兼容性与性能对比
- 🔒 **锁定障碍实证**：验证 1.9.x 的 `VarHandle.compareAndExchange`（API 33）突破约束
- ✅ **语法兼容性确认**：运行现有书源/订阅源回归用例，确认开源超集方向
- ⚡ **性能量化**：同脚本下 1.8.1 vs 1.9.1 解析/执行耗时对比（解释模式）
- 🧭 **升级路径决策**：minSdk 门槛 / 双引擎 flavor / 保持锁定 三选一

## 最终决策（🛑 用户确认：路径 B）

> **保持 Rhino 1.8.1 锁定**，本次不升级；沉淀里程碑「minSdk 提升 ≥33 时直跳 1.9.1」（详见 tasks.md `M.milestone`）。

| 维度 | 实测值 | 说明 |
|------|--------|------|
| 语法兼容 | 26/26 段 100% 一致 | 1.9.x 为 ES6 超集，`VERSION_ES6` 锁定下零回归 |
| 书源型性能 | ≈**+31%** | 正则/字符串/JSON 密集负载贴近真实解析 |
| 运行时安全性 | ✅ 安全 | 探针证实 `SlotMapOwner$ThreadedAccess` 永不加载 |
| 唯一剩余障碍 | **构建期 D8 反糖化** | desugar 不覆盖 VarHandle，需 minSdk≥33 或 D8 Spike 放行 |
