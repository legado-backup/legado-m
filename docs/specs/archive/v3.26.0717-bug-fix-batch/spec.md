# Spec - v3.26.0717 真机测试 Bug 批量修复

## Intent

针对 v3.26.071619debug 版本真机测试发现的 6 个问题，按"先根因定位、后精准修复、最小侵入式改动"原则进行批量修复。每个修复点必须可独立验证、可独立回滚，避免一个修复影响其他功能。

## Scope

### In Scope（本次实现）

| # | 问题 | 修复范围 |
|---|------|---------|
| 1 | 订阅源编辑页解析并发显示 0 | `RssSourceEditActivity.kt` 显示逻辑 |
| 2 | 高亮规则颜色选择器暗色主题下预设色块全显示白色 | `HighlightRuleEditDialog.kt` + ColorPickerDialog 主题适配 |
| 3 | 替换规则崩溃 ConcurrentModificationException | `ReadBook.kt` 并发安全 |
| 4 | 其他设置 rss/图片并发下方文字不显示当前值 | `OtherConfigFragment.kt` summary 显示 |
| 5 | 域名分组/智能排序/反序三类问题 | `BookSourceActivity.kt` + `BookSourceViewModel.kt` |
| 6 | 书源/订阅源视图布局与书架对齐 | 评估 + 必要修复 |

### Out of Scope（本次不实现）

- 订阅源登录后 articles=0 问题（已搁置）
- 网络层 Cronet 协议优化（独立任务）
- 书源规则引擎重构（独立任务）

## Approach

### Selected Approach

**分问题独立修复 + 真机回归验证**：
- 每个问题独立定位根因 → 独立修复 → 独立编译验证
- 全部修复完成后统一编译 + 真机测试
- 修复过程中遵循"最小侵入"原则，不重构无关代码

**理由**：
- 6 个问题分布在 6 个不同模块，互不影响
- 分问题修复便于回滚和定位
- 符合 coding-philosophy.md "精准修改"原则

### Alternatives Considered

| 方案 | 描述 | 否决理由 |
|------|------|---------|
| 全量重构视图层 | 重新设计 BookSourceAdapter/Grid 体系 | 改动面过大，回归风险高，违背"最小侵入"原则 |
| 替换 ColorPickerDialog 库 | 用自定义颜色选择器替代第三方库 | 工作量大，原库功能完善，只需主题适配 |
| 重写 ruleMatchesOfChapter 缓存机制 | 用 Room + Flow 替代 ArrayList | 改动面大，超出"修复崩溃"需求范围 |

### Drawbacks

- **Drawback 1**：问题 5 域名分组修复可能影响用户已有的分组排序习惯
  - 接受理由：当前排序逻辑本身有 Bug（不按权重排序），修复后更符合用户预期
- **Drawback 2**：问题 2 ColorPickerDialog 主题适配依赖第三方库内部实现
  - 接受理由：第三方库已稳定，主题适配通过 dialog Context 包装可实现

### Prior Art

- 前序 HighlightStyleDialog 主题适配经验（Phase 10 Issue-17）
- AGENTS.md G4 规范：DialogFragment/BottomSheetDialogFragment 主题适配

## Requirements

### R1：订阅源解析并发显示（问题 1）

- **R1.1**：当单源 `parseConcurrency > 0` 时，编辑页显示该具体值
- **R1.2**：当单源 `parseConcurrency = 0`（未配置）时，编辑页显示系统配置值，并标注"继承全局"
- **R1.3**：保留用户可单独配置的能力（不改变保存逻辑）

### R2：高亮规则颜色选择器主题适配（问题 2）

- **R2.1**：颜色选择器在亮色主题下预设色块显示正常颜色（黄/绿/蓝/粉/橙等）
- **R2.2**：颜色选择器在暗色主题下预设色块仍显示正常颜色，不全部显示白色
- **R2.3**：预设色块的文字标签在暗色主题下可读（不为白色）

### R3：替换规则崩溃修复（问题 3）

- **R3.1**：`ruleMatchesOfChapter` 在并发场景下不抛 `ConcurrentModificationException`
- **R3.2**：修复后不影响高亮规则的加载和缓存逻辑
- **R3.3**：保留 `@Volatile` 字段可见性语义

### R4：其他设置并发数显示（问题 4）

- **R4.1**：rss 解析并发 summary 显示当前设置数（如 "12"）
- **R4.2**：图片加载并发 summary 显示当前设置数
- **R4.3**：与 threadCount（更新线程数）的显示格式保持一致

### R5：域名分组/排序/反序修复（问题 5）

- **R5.1**：域名分组不再展示 "http"/"https" 作为分组名（异常 URL 处理）
- **R5.2**：搜索框过滤后，域名分组仅显示过滤后的书源（不混入未过滤项）
- **R5.3**：智能排序按权重从高到低（同组内也按权重降序）
- **R5.4**：反序复选框在所有排序模式（含域名分组）下都生效

### R6：书源/订阅源视图布局评估（问题 6）

- **R6.1**：评估当前 BookSourceAdapterCompact/Grid 与书架布局的差异
- **R6.2**：评估 RssSourceAdapterCompact/Grid 与书架布局的差异
- **R6.3**：列出需要修复的具体差异点（在 design.md 中详述）

## Scenarios

### S1：订阅源编辑页显示继承的全局并发数

1. 用户打开任一订阅源编辑页
2. 系统配置 rss 解析并发为 12
3. 该订阅源 `parseConcurrency = 0`（未单独配置）
4. **预期**：编辑页"解析并发"输入框显示 "12"，并标注"（继承全局）"
5. **现状**：编辑页显示为空或 0

### S2：暗色主题下颜色选择器预设色块正常显示

1. 用户切换应用为暗色主题
2. 用户进入高亮规则编辑页
3. 用户点击"填充色"或"字体色"按钮
4. **预期**：弹出的颜色选择器中，6 个预设色块分别显示黄/绿/蓝/粉/橙等颜色
5. **现状**：6 个预设色块全部显示白色

### S3：使用替换规则不崩溃

1. 用户在阅读小说时启用替换规则
2. 用户翻页触发 upHighlight
3. 同时另一线程调用 loadHighlightRules（如返回 Activity 触发 upHighlightRules）
4. **预期**：不崩溃，高亮规则正常应用
5. **现状**：抛 `ConcurrentModificationException` 崩溃

### S4：其他设置显示当前并发数

1. 用户进入"其他设置"
2. 当前 rss 解析并发为 12，图片加载并发为 8
3. **预期**：rss 解析并发条目下方显示 "12"，图片加载并发条目下方显示 "8"
4. **现状**：显示固定文案，不显示当前值

### S5：域名分组按权重排序 + 反序生效

1. 用户在书源管理页输入"校验成功"过滤
2. 用户勾选"按域名分组"
3. 用户切换排序为"按权重"
4. **预期**：分组列表中，每组内书源按权重从高到低排序
5. 用户勾选"反序"复选框
6. **预期**：每组内书源按权重从低到高排序
7. **现状**：分组按 lastUpdateTime 排序，反序无效果
