# 用户价值导向的借鉴决策重评估

> **生成时间**：2026-07-18
> **触发原因**：用户反馈"AI 模块不建议加入，需要配置 API key，对用户使用软件没太大好处。其他模块也需要深度分析哪些是对当前系统做了优化改善且收益很大的"
> **评估标准**：**对用户使用软件的实际好处**（非技术新颖度）
> **核心问题**：这个借鉴点能让用户用得更爽吗？还是只是技术上更酷？

---

## 一、重评估方法论

### 1.1 评估维度（按重要性排序）

| 维度 | 权重 | 说明 |
|------|------|------|
| 用户直接感知 | 40% | 用户能立刻感受到的好处（如加载更快、操作更方便） |
| 用户核心场景 | 30% | 是否覆盖阅读 App 的核心场景（看书/订阅/视频） |
| 实施成本 vs 用户收益 | 20% | 投入产出比 |
| 用户额外负担 | 10% | 是否需要用户额外配置（如 API key） |

### 1.2 用户价值评分（1-5 分）

- **5 分**：用户核心场景 + 直接感知 + 低成本 + 无额外负担
- **4 分**：用户直接感知 + 低成本
- **3 分**：用户间接感知 或 中等成本
- **2 分**：开发者侧优化 或 用户感知弱
- **1 分**：纯技术架构 或 需要用户额外配置

### 1.3 决策规则

- **用户价值 ≥4 分**：保留为 P0/P1 借鉴
- **用户价值 =3 分**：降级为 P2 或待评估
- **用户价值 ≤2 分**：改为不借鉴

## 二、AI 模块全量否决（用户明确反对）

### 2.1 否决理由

用户原文："AI 模块，我都不建议加入到我的项目中去，因为收益太小了，还需要配置模型 api key，并且其实对用户使用该软件没有太大的好处！"

### 2.2 AI 模块所有借鉴点改为不借鉴

| 决策ID | 决策项 | 原优先级 | 新决策 | 否决理由 |
|--------|--------|---------|--------|---------|
| AI-B-01 | MCP 客户端 | P0 | **不借鉴** | 需 API key，用户收益小 |
| AI-B-02 | Tavily 联网搜索 | P0 | **不借鉴** | 需 API key，用户收益小 |
| AI-B-03 | AiResolvedTool 抽象 | P1 | **不借鉴** | 依赖 AI 模块 |
| AI-B-04 | 上下文压缩机制 | P1 | **不借鉴** | 依赖 AI 模块 |
| AI-B-05 | JS 脚本生图 | P2 | **不借鉴** | 依赖 AI 模块 |
| AI-B-06 | 完整 AI Agent 架构 | P2 | **不借鉴** | 依赖 AI 模块 |

**结论**：AI 模块 8 项借鉴全部改为不借鉴。本项目定位为"阅读器"，不是"AI 助手"。AI 能力对用户核心场景（看书/订阅/视频）没有直接帮助，且需要用户配置 API key 增加使用门槛。

## 九、用户价值导向的核心结论

### 9.1 重新评估后的"用户高收益"借鉴点（Top 9）

**这 9 项是真正能让用户用得更爽的借鉴点**：

1. **RssSearchActivity** - 让用户可以搜索订阅内容（数据已就绪，104 行激活）
2. **markwon 3 扩展** - 让订阅文章渲染更完整（删除线/任务列表/链接）
3. **纸墨风格** - 让阅读视觉体验更好（60 行代码）
4. **VideoBookPreloader** - 让视频播放更快（90 行代码）
5. **SourceSelectDialog** - 让源管理更简单
6. **SearchBookMergeUtils** - 让搜索结果统一查看
7. **EPUB 章节资源索引** - 让 EPUB 加载更快
8. **EPUB 资源过滤 + 标题归一化** - 让 EPUB 阅读体验更好
9. **字体撞色检测** - 避免用户设置错误配色

### 9.2 重新评估后的"用户无感知"借鉴点（降级或否决）

**这些借鉴点对用户没有直接好处，不应该高优先级实施**：

- AI 模块全部（需 API key，收益小）
- liquidglass/miuix/lottie（增加体积，视觉特效）
- AppearanceKit/KirBinding（技术架构）
- CI 优化（开发者侧，用户无感知）
- composeBom 升级（技术升级）

### 9.3 关键启示

1. **用户价值 > 技术新颖度**：评估借鉴点时，首先问"这能让用户用得更爽吗？"
2. **核心场景 > 边缘场景**：聚焦看书/订阅/视频三大核心场景
3. **实施成本 vs 用户收益**：60 行代码的纸墨风格 > 16000 行的 EPUB 引擎
4. **用户额外负担是减分项**：需要 API key 的功能用户价值大打折扣
5. **数据已就绪的借鉴点优先级最高**：如 RssSource.searchUrl 字段已有但无 Activity 使用
