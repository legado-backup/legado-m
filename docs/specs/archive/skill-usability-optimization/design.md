
## 方向 2：分级工作流

### 2.1 快速路径（简单场景）

**触发条件**（满足任一）：
- 检测到已知 CMS 类型（WordPress/Typecho/Z-Blog 等，通过 cms-samples 匹配）
- 网站是静态 HTML（无 JS 渲染、无反爬、无登录）
- 用户明确要求"快速生成"

**流程**：
```
1. 分析网站 → 检测 CMS 类型 → 复用 cms-samples 选择器 → 构建规则
2. 运行 verify-source.py → 输出 JSON + 标注可信度
```

**跳过的阶段**：Phase 1（经验搜索）、Phase 4（源码深挖）、Phase 5（经验反哺）

**完成标志**：`[QUICK_PATH_COMPLETE] CMS类型:XXX, 验证:通过/失败`

### 2.2 标准路径（中等复杂度）

**触发条件**：
- 非 CMS 网站，但无 CF/登录/加密
- 需要自定义选择器

**流程**：精简 5 阶段
- Phase 1：快速搜索 basic-memory（1 次搜索，不迭代）
- Phase 2：构建规则 + 预校验
- Phase 3：运行 debug-source.py
- Phase 5：经验反哺（仅写入 basic-memory，不更新 references/）

### 2.3 完整路径（复杂场景）

**触发条件**：
- CF 反爬 / 登录 / 验证码 / 加密 / 视频站
- 测试失败需要源码深挖

**流程**：完整 5 阶段（保持现有流程）

### 2.4 路径选择决策树

```
网站分析结果
├─ 已知 CMS 类型？ → 快速路径
├─ 静态 HTML 无 JS？ → 快速路径
├─ 有 CF/登录/加密？ → 完整路径
├─ 测试失败需源码深挖？ → 完整路径
└─ 其他 → 标准路径
```

## 方向 3：统一 basic-memory 降级策略

### 3.1 统一降级流程

```
1. 检测不可用：调用 mcp_basic-memory_search_notes，若异常或超时
2. 告知功能边界：输出"⚠️ basic-memory 不可用，以下功能受限：{具体功能列表}"
3. 提供替代方案：
   - source-creator：跳过 Phase 1 经验搜索，标注"无经验参考"
   - workflow-auditor：切换到降级模式（检查 output 目录 + 执行 verify-source.py）
   - skill-auditor：跳过 E 维度，标注"需 basic-memory 验证"
4. 标记待验证：输出中标注"basic-memory 降级模式"
```

### 3.2 降级模式下的功能边界

| Skill | 正常模式 | 降级模式 | 不可用功能 |
|-------|---------|---------|-----------|
| source-creator | 5 阶段完整 | 跳过 Phase 1，标注"无经验参考" | 经验检索、经验反哺 |
| workflow-auditor | 8 项检查 | 3 项检查（output 目录 + verify-source.py + 上下文标志） | basic-memory 执行证据检查 |
| skill-auditor | 8 维度 42 项 | 7 维度 35 项（跳过 E 维度） | basic-memory 双向同步检查 |

## 方向 7：增强 workflow-auditor 独立价值

### 7.1 增加实际验证能力

**新增步骤**：在步骤 3（逐项检查）后，新增步骤 3.5（实际验证）：

```
步骤 3.5：实际验证（新增）
  → 检查 output/book/ 或 output/rss/ 下是否存在输出文件
  → 执行 verify-source.py 验证源完整性
  → 如果源不完整，标记 ERROR 并提供修复建议
```

### 7.2 减少 basic-memory 依赖

**当前 8 项检查的依赖分析**：

| 检查项 | 依赖 basic-memory？ | 降级替代方案 |
|--------|-------------------|-------------|
| Phase 1 执行证据 | 是 | 检查上下文 [PHASE1_COMPLETE] 标志 |
| Phase 3 执行证据 | 是 | 检查 output 目录 + 执行 verify-source.py |
| Phase 5 执行证据 | 是 | 检查上下文 [PHASE5_COMPLETE] 标志 |
| 陷阱检查 | 是 | 检查上下文 |
| 测试覆盖率 | 是 | 执行 verify-source.py 获取实际覆盖率 |
| 经验反哺 | 是 | 检查上下文 |
| 代码进化 | 是 | 检查上下文 |
| Phase 完成标志 | 否 | 检查上下文 |

**优化后**：8 项中 4 项可降级（不依赖 basic-memory），降级模式下仍有 4 项可用。

### 7.3 增强审计报告

**当前格式**：只有通过/失败

**优化后格式**：
```
| 检查项 | 状态 | 详情 | 错误原因 | 修复建议 |
```

## 方向 8：统一触发词和上下文传递

### 8.1 简化触发词表

**当前 12 个触发词** → **优化为 5 个**：

| 触发词 | 归属 skill | 说明 |
|--------|-----------|------|
| 书源/订阅源/阅读/Legado | source-creator | 核心 |
| 审计（任务） | workflow-auditor | 任务执行证据 |
| 审查 skill | skill-auditor | skill 本身质量 |

**当前 5 个字段** → **优化为 2 必填 + 1 可选**：

| 字段 | 必填/可选 | 说明 |

## Architecture Decisions（架构决策）

### AD-1：SKILL.md 定位为"决策入口"而非"全量知识库"

**决策**：SKILL.md 只保留决策所需信息，详细内容下沉到 references/。

**理由**：514 行 SKILL.md 消耗大量上下文，AI agent 读取后剩余上下文不足以完成复杂任务。

**影响**：AI agent 需要按需读取 references/，但总体上下文消耗降低 60%+。

### AD-2：分级工作流而非一刀切 5 阶段

**决策**：支持快速/标准/完整三级工作流，AI 根据网站特征自动选择。

**理由**：简单 CMS 网站不需要 5 阶段流程，过度设计降低效率。

**影响**：简单场景执行效率提升 60%+，复杂场景不受影响。

### AD-3：移除"设计中"功能描述

**决策**：SKILL.md 只描述已实现功能，未实现功能不写入。

**理由**："实现状态：设计中"标记让使用者困惑，无法判断 skill 实际能力。

**影响**：SKILL.md 内容与实际实现 100% 一致，消除歧义。

### AD-4：skill-auditor 默认执行核心 10 项检查

**决策**：默认执行 L1 快速检查（10 项），用户可显式要求标准/深度。

**理由**：42 项检查一次性执行成本太高，AI 经常只执行部分。

**影响**：审查执行完整率从 ~40% 提升到 ~90%。

### AD-5：workflow-auditor 增加实际验证能力

**决策**：workflow-auditor 新增"实际验证"步骤，执行 verify-source.py。

**理由**：当前只检查"执行证据是否存在"，不验证"源是否真的可用"，价值有限。

**影响**：workflow-auditor 独立价值提升，减少对 basic-memory 的依赖。

## Data Flow（数据流）

### 优化后的 source-creator 数据流

```
用户输入网站 URL
  ↓
网站分析 → 检测 CMS 类型 / 网站特征
  ↓
路径选择
  ├─ 快速路径：复用 CMS 选择器 → 构建规则 → verify-source.py → 输出
  ├─ 标准路径：精简 5 阶段
  └─ 完整路径：完整 5 阶段
  ↓
输出 JSON + 可信度标注
```

### 优化后的 skill-auditor 数据流

```
用户触发审查
  ↓
默认执行核心 10 项检查（5 分钟）
  ↓
用户要求标准/深度？
  ├─ 是 → 追加执行标准/深度检查
  └─ 否 → 输出核心审查报告
  ↓
输出审查报告（3 部分）
```

### 优化后的 workflow-auditor 数据流

```
source-creator 任务完成
  ↓
接收上下文（source_name + source_type 必填）
  ↓
basic-memory 可用？
  ├─ 是 → 8 项完整检查
  └─ 否 → 4 项降级检查（output 目录 + verify-source.py + 上下文标志）
  ↓
新增：实际验证（执行 verify-source.py）
  ↓
输出审计报告（含错误原因 + 修复建议）
```
