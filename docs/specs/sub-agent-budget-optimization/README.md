# 子代理编排与思考预算优化

> **状态**：✅ 已完成（检查点2通过，所有任务实施完成+验证通过）
> **创建日期**：2026-07-12
> **功能类型**：规范体系优化（非代码变更）

## 功能概述

通过强制子代理编排，规避 GLM-5.2 在 Trae 平台触发"模型思考次数已达上限"的问题。核心思路：**用子代理在同对话内"虚拟地"拆分任务**，既扩展工作量又不增加成本（不额外开新对话）。

## 核心能力

1. **强制子代理触发条件**：≥5 文件 / ≥10 工具调用 / 深度分析任务
2. **主代理监控机制**：同步等待 + TaskOutput 查询 + SendMessage 补充
3. **质量保证体系**：明确 prompt + 主代理二次验证 + 失败重试
4. **规范冲突处理**：与"并发文件修改规范"等现有规范的协调方案
5. **禁止建议新对话**：新对话收费，触发上限时优先"继续"或子代理分担

## 背景与痛点

- GLM-5.2 在 Trae 平台有"思考次数上限"（工具调用轮次+思考 token+上下文累积）
- 触发后需输入"继续"续接，频繁触发导致用户体验差
- 新对话收费（一次新对话一次钱），所以不能靠"拆分到多次对话"解决
- 子代理有独立预算且不额外收费 = **对话内的虚拟新对话**
