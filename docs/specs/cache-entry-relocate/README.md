# "我的"页功能归堆重构（cache-entry-relocate）

## 状态

🔄 开发中（2026-08-28 终审通过，按 tasks.md 2.1-2.8 实施）

## 功能概述

由用户疑问"同步与服务里的缓存管理与精准管理里的存储管理是不是一码事"引发，经三轮 scope 演进（缓存入口迁移 → +诊断三件套迁移 → 全量归堆），最终形态为**"我的"页系统性归堆重构**：

1. **缓存管理入口迁移**：同步与服务 → 精准管理数据管理卡片（存储管理与下载管理之间）
2. **诊断三件套迁移**：崩溃日志/保存日志/创建堆转储从"关于 → 其他"整体迁入精准管理新"日志与诊断"卡片（方法逐字节平移零行为变化）
3. **全量归堆（6 组）**：24 行按功能域重组——内容与规则(6)/外观(3)/同步与服务(3)/工具(7)/精准管理(1)/关于(2)；高亮规则归规则组、AI 设置归工具组、关于/退出独立成组、网址记录消双入口（对齐 bugfix-20260824 文件管理先例）

页面能力本体零改动、零功能增删、零数据流/零数据库变更。

## 核心能力

| 变更点 | 说明 |
|--------|------|
| 6 组归堆 | 名实一致补完（现状组名已含归堆意图但行归位未跟上） |
| 缓存入口迁移 | 同步与服务 → 精准管理数据管理卡片 |
| 诊断三件套迁移 | 精准管理新"日志与诊断"卡片，关于页瘦身为纯信息类 |
| 网址记录消双入口 | 工具组一级行删除，仅精准管理一处（先例：文件管理） |
| 两卡片都加标题 | "数据管理" + "日志与诊断"（用户裁决，视觉对称） |
| 搜索自动跟随 | 设置搜索页与我的页共用 buildSettingsSections，6 组结构自动跟随 |

## 背景澄清（为什么不是"融合两个页面"）

| 对比 | 缓存管理（CacheManageActivity） | 存储管理（StorageManageActivity） |
|------|------|------|
| 维度 | 内容/任务：管理已缓存书籍/音频/漫画（三 Tab），可缓存章节、上传云端、删除 | 空间：各类缓存目录磁盘占用统计与清理 |
| 摘要 | "统一管理书籍、音频和漫画缓存。" | "查看与清理缓存存储" |

## 可行性核查（C1-C10 全 PASS，详见 design.md）
