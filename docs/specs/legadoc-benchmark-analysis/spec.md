# spec.md — legadoc-benchmark-analysis

## Intent

对 CCSSNE/legadoC（阅读C，own 分支）做源码级深度对标：识别其相对本项目的优势与本项目劣势/优势，产出可实施的迁移功能清单与函数级设计，**独立成 spec**（不与 ng-benchmark-analysis 合并），设计文档达到"完全支撑后续开发实施"标准。

## Scope

**做什么**：仓库定位与源码快照；四能力域深读+四维逐文件 diff；双向优缺点；决策表；C0-C5 六期实施级设计；≥5 轮自主交叉验证（一致性/锚点/规范/可实施性/终审+红队+终复审）。
**不做什么**：不实施代码；不覆盖 NG 任务结论（叠加性已验证但不合并文档）；不分析业务数据。

## Approach

zipball 快照+能力域深读+逐文件 diff 双轨（沿用 NG 任务已验证方法）；六期实施级设计起步即函数/代码级；交叉验证自主循环。

### Alternatives Considered
| 方案 | 否决理由 |
|------|---------|
| 与 NG spec 合并 | 对象/分期/结论体系不同；用户明确要求独立 |
| 仅域深读不做 diff | NG 经验证明会漏判超集事实与本项目 bug |
| git clone | NG 实测网络停滞，zipball 等价且快 |

### Drawbacks
- 快照时效（legadoC 高频迭代，锚点以快照为准可复跑）
- 纯 View 体系借鉴需"模式翻译"，UI 层不可照搬
- 血统不同（Archive 系）导致部分 diff 基线噪音大

## Requirements

R1 仓库身份/版本/活跃度确认；R2 朗读架构逐函数解读与迁移面；R3 AI/多媒体/融合机制；R4 前端番茄化+设计系统；R5 工程治理/CI/DB/日志/安全；R6 四维 diff；R7 双向优缺点+决策表；R8 C0-C5 函数级设计（规范核查表+6 维门禁+测试设计）；R9 ≥5 轮交叉验证留痕；R10 全部结论带文件:行证据。

## Scenarios

- S1 用户审查后裁决分期顺序 → 各期另立实施 spec
- S2 某期深化不足 → 指定下钻追加轮
- S3 legadoC 重大更新 → 按快照锚点复跑
