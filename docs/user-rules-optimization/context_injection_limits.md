## 二、注入顺序机制

### 2.1 注入规则

```
按修改时间从旧到新 → 逐个注入 → 达到配额后停止
```

### 2.2 注入顺序示例

假设有5个文件，按修改时间排序：

```
[旧] user_rules.md (3KB)
[旧] danger-ops.md (1KB)
[中] rule-1782963384927.md (3.1KB)
[中] output-safety.md (1.9KB)
[新] core-spec.md (0.9KB)
─────────────────────────────
合计：9.0KB < 12KB → 全部注入 ✓
```

如果新增文件（如 coding-philosophy.md 4KB）：

```
[旧] user_rules.md (3KB)
[旧] danger-ops.md (1KB)
[中] rule-1782963384927.md (3.1KB)
[中] output-safety.md (1.9KB)
[新] core-spec.md (0.9KB)
[新] coding-philosophy.md (4KB)
─────────────────────────────
合计：13KB > 12KB → 最后一个文件可能被截断或省略 ✗
```

### 4.3 验证结果

| 项目 | 结果 |
|------|------|

| 子代理看到rule文件版本 | 旧版（含成本对比表） |

### 4.4 关键发现

**系统注入在对话开始时固定**：
- 修改文件后，本对话内子代理只能验证旧状态
- 需要开新对话才能验证新状态

### 4.5 验证代码示例

## 五、超配额处理方案

### 5.1 问题场景

当规范文件总大小超过12KB配额时：
- 后注入的文件会被截断或省略
- AI可能无法获取完整的规范内容
- 违反"禁止仅根据记忆执行"的规则

### 5.2 处理方案

| 方案 | 说明 | 优先级 |
|------|------|--------|
| **精简大文件** | 去掉版本号/变更记录/铁证等冗余内容 | ⭐⭐⭐⭐⭐ |
| **拆分多文件** | 核心内容保留，详细内容拆分到子文件 | ⭐⭐⭐⭐ |
| **按需加载** | 任务开始时手动用Read工具加载所需规范 | ⭐⭐⭐ |
| **压缩恢复后加载** | 上下文压缩后强制读取core-spec.md索引 | ⭐⭐⭐ |

### 5.3 精简示例（rule-1782963384927.md）

**精简前**（9.2KB）：
- 包含版本号、变更记录、成本对比表等元信息
- 包含大量示例代码
- 包含详细的历史背景说明

**精简后**（3.1KB）：
- 只保留核心规则（禁止行为清单）
- 只保留正向和反例对比
- 去掉所有元信息和冗余内容

## 六、注入状态检查方法

### 6.1 检查时机

| 时机 | 必须 | 说明 |
|------|------|------|
| 上下文压缩恢复后 | **是** | 必须先并行读取四件套 |
| AskUserQuestion响应后 | **是** | 必须确认用户选择后继续 |
| 每个Phase完成后 | **是** | 持久化决策到memory |
| 开始新任务前 | **推荐** | 确认加载了所需子规范 |

### 6.2 检查方法

```python
# 方法1：检查系统注入内容
def check_injection():
    # 检查核心5文件是否完整注入
    required_files = [
        "user_rules.md",
        "danger-ops.md",
        "rule-1782963384927.md",
        "output-safety.md",
        "core-spec.md"
    ]

    for file in required_files:
        if is_injected(file):
            print(f"✓ {file} 已注入")
        else:
            print(f"✗ {file} 未注入，需手动加载")

# 方法2：手动加载按需文件
def load_subspec(task_type):
    subspec_map = {
        "openspec": "openspec-workflow.md",
        "code_change": "logging-during-refactoring.md + version-delivery-sync.md",
        "complex": "complex-task.md",
        "e2e_test": "ai_e2e_testing_workflow.md",
        "source": "SKILL.md"
    }

    subspec = subspec_map.get(task_type)
    if subspec:
        content = Read(f"~/.trae-cn/user_rules/{subspec}")
        print(f"已加载子规范: {subspec}")
        return content
```

## 八、最佳实践建议

### 8.1 规范文件设计原则

1. **核心文件保持精简**：≤10KB，只保留核心规则
2. **详细内容拆分到子文件**：按需加载，不占用注入配额
3. **去掉所有元信息**：版本号/变更记录/铁证等不应出现在规范文件中
4. **参考rule-1782963384927.md结构**：只有"错误做法 vs 正确做法"对比

### 8.2 任务执行前检查清单

- [ ] 确认当前任务类型

- [ ] 检查项目记忆中的"用户反馈与决策记录"
- [ ] 检查是否需要遵循Hard Constraints

### 8.3 上下文压缩恢复后必须执行

1. 并行读取四件套（AGENTS.md + project_memory.md + TaskList + basic-memory）
2. 输出验证清单
