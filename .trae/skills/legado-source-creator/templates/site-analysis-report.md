# 网站分析报告

> **报告用途**：AI 在 legado-source-creator skill 工作流中分析网站时输出的结构化工作笔记，作为生成源 JSON 的中间产物。AI 基于此报告可快速、准确地生成源 JSON，避免重复分析。
>
> **存放路径**：
> - 书源 → `output/ai_source/book/{域名}/`，与源 JSON 同名（如 `源A.json` 对应 `源A.report.md`）
> - 订阅源 → `output/ai_source/rss/{域名}/`，与源 JSON 同名
> - 域名取源 URL 的 host（小写、去 `www.`、去端口）；被取代的旧版迭代在 `{域名}/history/`
>
> **防上下文压缩说明**：本报告用于持久化分析过程中的关键发现，防止上下文压缩丢失数据。AI 自驱使用，无需用户介入。报告填充后即使上下文被压缩，AI 仍可基于本报告继续完成源 JSON 生成。
>
> **经验来源标注规则**（v8 强制）：经验来源必须用**通用范式名**（如 `动态域名修复范式`、`平衡括号算法`、`CMS API 嗅探范式`），**禁止用站点代号**。
>
> **偏好优先级标注规则**：视频源专用，标注提取方式的优先级（如 `[偏好优先级:视频地址提取P1-CMS API]`、`[偏好优先级:视频地址提取P2-页面嗅探]`）。

**字段备注**：
- `sourceUrl`：源入口 URL，若站点有动态域名，需填入含 `<js>` 动态计算的入口（标注 `[经验来源:动态域名修复范式]`）。
- `searchUrl`：搜索 URL 模板，GET/POST 方法、编码方式、分页参数均需明确。
- `sortUrl`：分类导航 URL，多分类用 `\n` 分隔，格式 `分类名::URL`。
- `ruleArticles`：列表项选择器，CSS/XPath/JSONPath 任选其一。
- `ruleTitle` / `ruleLink` / `ruleImage`：相对 `ruleArticles` 的子选择器或字段路径。
- `ruleNextPage`：下一页选择器或 URL 规则，相对列表页。
- `rulePubDate`：相对 `ruleArticles` 的时间子选择器，取列表项内发布/更新时间（如 `2026-08-18`、`3小时前`）；真机列表页时间行直接展示（RssArticlesAdapter1/2 的 tvPubDate）。
- `ruleDescription`：相对 `ruleArticles` 的简介子选择器，解析进 `RssArticle.description`；站点列表项上的类型标签/集数/作者等无独立字段的描述性信息，按下方 1.1 章方案合并进此字段。
- `ruleContent`：详情页内容提取规则；视频源若用内置嗅探，填空字符串 `""` 并标注 `[经验来源:嗅探模式]`。
- `ruleRoutes` / `ruleEpisodes`：视频源专用，多线路多集解析规则。

> 以下项需在真机/模拟器上验证，确认源 JSON 实际可用。

- [ ] **入口可达性**：sourceUrl 是否能正常加载列表

- [ ] **分类导航**：sortUrl 各分类是否能加载

- [ ] **详情页解析**：ruleArticles 列表项是否能正确解析

- [ ] **编码处理**：GBK 等非 UTF-8 编码是否正确显示

## 附：经验来源通用范式名参考

> 以下为常用通用范式名，AI 填写经验来源标注时应优先使用这些范式名，禁止使用站点代号。

- `动态域名修复范式`：站点入口域名动态变化，需用 `<js>` 实时计算真实域名
- `平衡括号算法`：处理嵌套括号、JSON 转义等复杂字符串
- `CMS API 嗅探范式`：通过 CMS 标准 API（如 player+url 参数）提取视频地址
- `嗅探模式`：ruleContent 设为空字符串触发内置 WebView 嗅探
- `MacCMS 标准解析`：MacCMS 站点的标准多线路多集解析规则
- `GBK 编码范式`：处理 GBK 编码站点的搜索参数编码
- `相对路径补全范式`：将相对 URL 补全为绝对 URL
- `OG 元数据范式`：利用 Open Graph meta 标签提取标题/图片
- `下一页 URL 范式`：通过 nextUrl 实现分页
- `Cookie 缓存范式`：缓存登录 cookie 用于后续请求
