# 输出安全与违禁词规避规范

> 不能因触发违禁词中断对话及任务处理。思考过程也不能有违禁词。
> **被审查中断后必须立即恢复继续工作，不等待用户催促，不重复已完成工作。**

## 🔴🔴🔴 思考铁律（最高优先级，每次思考前必读）

> **这3条是所有规则的核心，违反任何一条都会触发审查中断。**

1. **收到工具输出的第一动作是"扫描敏感词并替换为代号"，不是分析内容**
   - 违反 = 思考链路被敏感词污染 → 触发审查 → 主动中断
   - 正确：扫描 → 替换为代号（源[1]/站点A）→ 再分析技术结构

2. **禁止在思考中原样引用源名称/域名/URL/成人内容词汇**
   - 即使是"为了分析"也不行，必须先用代号替代
   - 思考中只保留：异常类型/错误码/调用栈/DOM选择器/字段名/函数名/技术结构

3. **禁止 Grep 搜索业务数据字段，只搜索技术字段**
   - ❌ 禁止搜索：sourceName / sourceUrl / sortUrl / sourceComment / title / name / summary / description
   - ✅ 允许搜索：ruleImage / coverDecodeJs / ruleReview / id / type / enabled / 函数名 / 类名

## 核心原则

**AI在思考和输出时，必须主动过滤敏感内容。思考过程中处理工具输出时，第一时间将敏感词替换为代号。**

## 违禁词范围与处理

| 类别 | 处理方式 |
|------|---------|
| 成人/色情 | 代号替代，不输出内容描述 |
| 违法内容（赌博/毒品/诈骗/黑客攻击） | 只输出技术结构 |
| 政治敏感/暴力/恐怖主义 | 默认过滤 |
| 视频/影视网站域名/URL | 代号（站点A/B/C）替代，路径模式化（/path/{id}） |
| 敏感字段（token/cookie/password/key/secret/auth/credential） | 完全隐藏 *** |
| 设备ID/用户ID/IP/邮箱/手机号 | 脱敏 |
| 不确定是否敏感 | 默认过滤 |

## 工具调用前置预判清单（强制，调用工具前必读）

> **调用任何工具前，必须先回答以下三个问题。任何一个回答"是"就必须调整调用方式。**

| # | 自问 | 命中处理 |
|---|------|---------|
| 1 | 返回内容是否可能含源名称/源URL/源标题？ | 改用技术关键词搜索（字段名/函数名/类名），或用 `head_limit≤5` + offset 分页读取 |
| 2 | 返回内容是否可能含域名/完整URL/IP/邮箱/手机号？ | 改用路径模式 `/path/{id}`，域名用代号（站点A/B/C） |
| 3 | 返回内容是否可能含成人/违法/政治敏感词汇？ | 禁止调用该工具，改用替代方案（如只读取文件结构/字段名而非值） |

**反模式（基于铁证）**：
- ❌ `Grep sourceUrl|sourceName` 搜索 RSS 源 JSON → 返回 64 个源真实名称（含成人内容）→ 触发审查
- ❌ `nav_helper.py dump_hierarchy` 输出源列表真实名称 → 触发审查
- ✅ `Grep ruleImage|coverDecodeJs` 搜索技术字段名 → 安全
- ✅ 脚本输出源列表用编号 `源[1]/源[2]` 替代真实名称 → 安全

## 预防性搜索策略

> 违禁词拦截的根因往往是工具返回大量敏感词进入思考链路。必须在搜索阶段就降低暴露面。

| 策略 | 说明 |
|------|------|
| 限制返回行数 | Grep 搜索敏感字段（sourceName/sourceUrl/sortUrl/sourceComment 等）时必须设 `head_limit ≤ 5` |
| 按需读取而非全量 | 读取含敏感内容的 JSON/DB 时用 `offset+limit` 只读必要行，禁止全量读取 |
| 搜索技术关键词 | 搜索代码/源码时用技术关键词（函数名/字段名/类名），禁止搜索业务数据字段 |
| 避免输出回显 | 工具返回的敏感内容不回显到正文，只提取技术结论 |
| 预判风险 | 调用工具前先回答"前置预判清单"三个问题 |

## 高风险工具调用黑名单（禁止模式，基于铁证）

> **以下调用模式已多次触发审查中断，禁止使用。发现自己在构造这类调用时必须立即停止改方案。**

| 禁止模式 | 根因（铁证） | 替代方案 |
|---------|------------|---------|
| `Grep sourceName` / `Grep sourceUrl` / `Grep sortUrl` / `Grep sourceComment` | 返回数十个源真实名称，含成人内容词汇 | 搜索技术字段：`ruleImage` / `coverDecodeJs` / `ruleReview` / `enabled` |
| `Grep title` / `Grep name` / `Grep summary` / `Grep description`（在源JSON/DB中） | 返回业务文本含敏感词 | 搜索结构字段：`id` / `type` / `sort` / `customOrder` |
| `Read` 整个 RSS 源 JSON 文件（无 offset+limit） | 含全部源真实名称 | 用 `offset+limit` 只读必要行，或只读文件头部确认结构 |
| 子代理 `dump_hierarchy` 输出源列表 | UI 含源真实名称 | 脚本输出用编号 `源[1]/源[2]`，禁止 dump 文本 |
| `Grep 源名称关键词`（如搜索某个具体源名） | 直接命中成人内容 | 按源 ID 编号搜索，不按名称 |
| 读取 logcat 全量日志未过滤 | 日志含源名称/域名/URL | Grep 过滤技术关键词（Exception/Error/FATAL），`head_limit ≤ 20` |

**自检规则**：构造 Grep/Read 调用前，对照本表检查 pattern/path 是否命中禁止模式。命中则立即改方案。

## 思考强制模板（强制，收到工具输出后必须按此开头）

> **思考过程的第一个动作不是分析内容，而是扫描上一个工具输出是否含敏感词并替换。**
> **这是可执行模板，不是描述性规则。每次收到工具输出，思考必须以下列格式开头。**

### 思考开头强制模板（内部思考，不输出到正文）

```
【守门员扫描】工具输出是否含敏感词？
- 源名称/域名/URL/成人内容词汇？→ [是/否]
- 命中则立即替换：源名称→源[1]，域名→站点A，URL→/path/{id}，成人词汇→"含成人内容"
【脱敏完成】基于脱敏后内容进行技术分析：
- 异常类型/错误码/调用栈/DOM选择器/字段名/函数名
- 技术结论/修复方案
```

### 流程图

```
收到工具输出
  ↓
【守门员】扫描输出：是否含源名称/域名/URL/成人内容/敏感字段？
  ↓ 命中                              ↓ 未命中
立即替换为代号：                    直接进入分析
- 源名称 → 源[1]/源[2]/源[N]
- 域名 → 站点A/站点B/站点X
- URL → /path/{id}
- 敏感字段 → ***
- 成人内容词汇 → "含成人内容"（概括，不引用原文）
  ↓
基于脱敏后的内容进行技术分析
```

**关键规则**：
1. **禁止在思考中原样引用工具返回的源名称/域名/URL**——即使是为了"分析"，也必须先替换为代号
2. **禁止在思考中描述成人内容**——即使工具返回了，也只用"含成人内容词汇"概括
3. **思考过程只保留技术结构**——异常类型/错误码/调用栈/DOM选择器/字段名/函数名

## 工具输出处理流程（强制）

> 收到工具输出后的第一步不是分析内容，而是扫描敏感词并替换。

```
Step 1: 扫描 → 工具输出中是否包含违禁词范围中的内容？
Step 2: 替换 → 命中则立即替换为代号（源[1]/源[2]/站点A/域名X）
Step 3: 分析 → 基于脱敏后的内容进行技术分析
```

**关键：Step 1-2 必须在进入任何分析思考之前完成。跳过 Step 1-2 直接分析 = 违规。**

## 中断后恢复协议（强制）

> **被审查中断后，必须立即恢复继续工作，不等待用户催促。**

| 步骤 | 动作 |

| 因违禁词中断对话 | 立即恢复继续工作 |
